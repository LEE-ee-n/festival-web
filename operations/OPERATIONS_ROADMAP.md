# Festibom 운영 준비 작업순서

운영 준비는 아래 순서대로 진행한다. 각 단계는 완료 기준을 통과한 뒤 다음 단계로 넘어간다.

## 1. 운영 기준과 반복 양식 고정

- 자동화: 운영 폴더와 날짜별 체크리스트 생성
- 수동: 일간·주간·월간·배포·장애 체크리스트 실행
- 완료 기준: 외부 운영 폴더가 생성되고 일간 점검 기록 1건이 남아 있음

## 2. DB 백업 신뢰성 확보

- 자동화: 매일 21:00 백업, 결과 기록, 보관기간 검사, 실패 알림
- 수동: 매주 최신 백업 구성과 파일 크기 확인
- 완료 기준: 수동 실행과 예약 실행이 모두 성공하고, 고의 실패 시 알림을 확인함

## 3. DB 복구 시험과 목표 확정

- 자동화: 복구 파일 무결성 검사와 소요시간 기록 보조
- 수동: 운영 DB가 아닌 격리 환경에 최신 백업 복원
- 완료 기준: 로그인·페스티벌·아티스트·개인 일정·페스티봄 일기 확인 완료
- 현재 잠정 목표: RPO 24시간, RTO 24시간

## 4. Storage 백업 구축

- 자동화: Supabase Storage 파일과 목록(manifest)을 로컬에 동기화
- 수동: 매월 임의 이미지 1개 복원 시험
- 완료 기준: 모든 버킷 백업, 누락 검사, 복원 시험 성공

## 5. 배포 안전장치 구축

- 자동화: GitHub에서 테스트·타입 검사·빌드 실행, 배포 후 공개 URL 점검
- 수동: 모바일 핵심 화면과 로그인·저장 기능 확인
- 완료 기준: 실패한 코드는 배포되지 않고 배포 체크리스트 기록이 남음

## 6. 장애 감지와 알림 통합

- 자동화: 홈페이지 응답, 주요 오류, 배포·백업 실패 감지
- 수동: 실제 알림을 받고 장애 체크리스트로 대응 연습
- 완료 기준: 고의 오류가 정해진 채널로 도착하고 원인·복구 기록이 남음

## 7. 운영 대장 구축

- 사용자 문의·삭제 요청
- 이미지와 정보 출처·사용 권리
- 외부 서비스 계정·2단계 인증·비용·만료일
- 완료 기준: 실제 사례를 각 대장에 1건씩 기록해 처리 흐름을 확인함

## 8. 월간 모의훈련과 매뉴얼 확정

- 백업 복구, 관리자 계정 분실, 배포 장애 중 하나를 매월 연습
- 실제 소요시간과 막힌 지점을 매뉴얼에 반영
- 완료 기준: 운영자가 문서만 보고 점검·복구·요청 처리를 반복할 수 있음

## 진행 원칙

1. 실제 데이터와 개인정보는 Git 저장소 밖 `Documents\FestibomOperations`에 둔다.
2. 자동화는 성공뿐 아니라 실패를 알려야 완료로 본다.
3. 자동화마다 수동 확인 방법을 남긴다.
4. 체크하지 않은 항목은 성공한 것으로 간주하지 않는다.
5. 운영 중 알게 된 새 절차는 즉시 해당 체크리스트에 반영한다.
