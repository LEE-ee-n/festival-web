# [완료] 기존 페스티벌 수정 비교표 전환 계획

- 작성일: 2026-07-26
- 상태: 코드 구현 및 자동 검증 완료 · 실제 화면 확인 대기
- 승인일: 2026-07-26
- 대상: `/admin/festivals/import-json?festivalId=...&updateDraftId=...`
- DB 변경: 없음

## 목적과 완료 조건

- 큰 비교 카드가 반복되어 화면이 길어지는 문제를 해결한다.
- 페스티벌 관리 화면처럼 조밀한 표에서 현재 값과 반영 후 값을 한눈에 비교하고 선택할 수 있게 한다.

## 확정 범위

### 공통 표시 규칙

- 배경색으로 상태를 구분하지 않는다.
- 상태 열의 기호와 글자로만 구분한다.
  - `➕ 신규 추가`
  - `✏️ 변경`
  - `❌ 삭제 후보`
  - `✅ 동일`은 기본적으로 화면에서 숨긴다.
- 현재 선택된 항목 수와 유지할 항목 수를 단계 상단에 간단히 요약한다.

### 기본정보·티켓

- 기존 큰 카드를 다음 열의 비교표로 바꾼다.
  - 상태
  - 항목
  - 현재 값
  - 새 값
  - 선택
- 선택 열에는 `현재값 유지`와 `새 값 반영` 상태를 한 버튼으로 전환한다.
- 설명·프로그램 정보처럼 긴 값은 기본적으로 일부만 보여주고 펼쳐서 전체를 확인할 수 있게 한다.
- 대표 썸네일도 같은 표의 한 행으로 표시한다.

### 타임테이블

- 다음 열의 비교표로 바꾼다.
  - 상태
  - 아티스트
  - 현재 일정
  - 새 일정
  - 선택
- 날짜·시간·무대를 한 줄 일정으로 표시한다.
- 신규 출연진은 `➕`, 일정 변경은 `✏️`, 명시적으로 취소된 출연진은 `❌`로 표시한다.
- 동일 일정은 기존처럼 비교 대상에서 숨긴다.

### 모바일

- 데스크톱에서는 표를 유지한다.
- 좁은 화면에서는 각 행의 제목·현재 값·새 값·선택 순서가 유지되도록 세로 행으로 전환한다.

## 제외 범위

- 검토 단계 순서 변경
- 비교·안전 병합·감사 로그 저장 규칙 변경
- 자동 삭제
- DB·RPC·RLS 변경
- 기본정보를 직접 입력해서 수정하는 기능

## 예상 수정 파일

- `app/admin/festivals/import-json/StagedFestivalUpdate.tsx`
- 비교표 전용 컴포넌트
- `lib/festivals/festivalUpdatePreview.ts`
- 관련 테스트
- `PROJECT_STATUS.md`

## 작업 순서

1. 기존 비교 상태를 화면용 `신규·변경·삭제 후보·동일` 상태로 변환하는 공통 함수를 만든다.
2. 기본정보·티켓 비교표와 타임테이블 비교표를 분리해 작성한다.
3. 대표 썸네일을 기본정보 비교표 행으로 합친다.
4. 기존 `UpdateChoices` 카드 UI를 비교표로 교체한다.
5. 선택 상태와 최종 반영 데이터가 기존과 동일하게 유지되는지 검증한다.
6. 타입 검사, ESLint, 관련 비교·병합 테스트를 실행한다.

## 회귀 위험과 검증

- `현재값 유지`와 `새 값 반영` 선택 결과가 뒤바뀌지 않는지 확인한다.
- 신규 추가 항목의 기본 선택 상태가 유지되는지 확인한다.
- 명시적 취소만 삭제 후보로 표시되고 자동 삭제되지 않는지 확인한다.
- 긴 설명과 URL이 표 너비를 밀어내지 않는지 확인한다.
- PC와 모바일에서 현재 값과 새 값의 순서가 혼동되지 않는지 확인한다.
- 최종 확정 단계의 선택 건수가 표에서 선택한 건수와 일치하는지 확인한다.

## 후속 개선점

- 변경된 단어만 강조하는 문장 단위 diff
- 동일 항목을 필요할 때만 펼쳐보는 기능

## 실제 결과

- 기본정보·티켓과 타임테이블의 큰 비교 카드를 공통 전후 비교표로 교체했다.
- 상태는 배경색 없이 `➕ 신규 추가`, `✏️ 변경`, `❌ 삭제 후보`로 표시한다.
- 동일 항목은 표에서 숨기고 단계 요약에 숨긴 건수만 표시한다.
- 표 위에 변경·반영 선택·현재 유지 건수를 표시한다.
- 대표 썸네일을 기본정보 비교표의 한 행으로 합쳤다.
- 긴 설명과 URL은 일부만 표시하고 펼쳐 전체 내용을 확인할 수 있게 했다.
- PC에서는 가로 비교표, 모바일에서는 상태·항목·현재 값·새 값·선택 순서의 세로 행으로 표시한다.
- 라인업의 새 일정은 누락된 기존 값을 보완한 최종 반영 예정값으로 표시한다.
- 기존 선택 ID와 최종 반영·감사 로그 저장 흐름은 변경하지 않았다.
- 비증분 타입 검사와 변경 파일 ESLint가 통과했다.
- 비교·안전 병합·감사 요약 관련 테스트 15건이 통과했다.
- localhost 실제 화면 확인은 사용자 환경에서 남아 있다.
