# [구현 완료·운영 설정 대기] GA4·Microsoft Clarity 방문 분석 연결 계획

## 목적과 완료 조건

- 공개 페이지의 방문·유입·주요 페이지 조회를 GA4에서 확인할 수 있다.
- 공개 페이지의 클릭·스크롤·사용 흐름을 Microsoft Clarity에서 확인할 수 있다.
- 관리자 컴포넌트는 만들지 않고 각 서비스의 외부 대시보드를 사용한다.
- 실제 분석 도구 사용 사실과 처리 범위를 개인정보처리방침에 반영한다.

## 확정 범위와 제외 범위

- 포함: GA4, Clarity 기본 스크립트 연결, 환경변수 이름 정의, 개인정보처리방침 갱신, 운영 설정 안내.
- 제외: 관리자 내부 방문자 대시보드, 개별 버튼 전환 이벤트, 광고 연동, 자동 인스타 업로드, 쿠키 동의 배너의 별도 구현.

## 예상 수정 파일·데이터 흐름

- `components/analytics/*`: 클라이언트 분석 스크립트 컴포넌트.
- `app/layout.tsx`: 모든 공개·관리 페이지에서 스크립트를 한 번만 로드.
- `app/privacy/page.tsx`: GA4·Clarity 처리 목적·항목·외부 처리자·쿠키 안내를 실제 설정에 맞게 갱신.
- `PROJECT_STATUS.md`: 설치 상태와 운영 확인 항목 갱신.
- 환경변수(사용자가 Vercel과 로컬에 직접 설정):
  - `NEXT_PUBLIC_GA_MEASUREMENT_ID`
  - `NEXT_PUBLIC_CLARITY_PROJECT_ID`
- 브라우저 방문 → 환경변수 값이 있을 때만 GA4·Clarity 스크립트 로드 → 각 외부 대시보드에서 집계 확인.

## 작업 순서

1. [x] 재사용 가능한 분석 스크립트 컴포넌트를 만들고 ID가 없는 환경에서는 로드하지 않도록 처리했다.
2. [x] 루트 레이아웃에 한 번 연결하고 `/admin` 경로는 분석 대상에서 제외했다.
3. [x] 개인정보처리방침을 실제 분석 범위에 맞게 갱신했다.
4. [ ] 사용자가 GA4 측정 ID와 Clarity 프로젝트 ID를 Vercel 환경변수에 설정한다.
5. [~] 타입 검사와 변경 파일 ESLint는 통과했다. 프로덕션 빌드는 컴파일·TypeScript까지 통과했으나 Codex 환경의 `.env.local` 접근 차단으로 기존 Supabase 정적 생성 단계에서 중단됐다. 배포 뒤 두 대시보드 수집 확인이 남아 있다.

## 회귀 위험과 검증 방법

- ID 미설정 개발 환경에서 외부 스크립트 오류가 발생하지 않는지 확인한다.
- 동일 스크립트가 중복 삽입되지 않는지 레이아웃 기준으로 확인한다.
- 개인정보처리방침의 기존 “분석 도구 미사용” 문구가 남지 않는지 검토한다.
- `npm run typecheck`, 변경 파일 ESLint, `npm run build`를 실행한다.

## 후속 개선점

- 필요해지면 `공식 인스타그램`, `티켓`, `축제 상세` 클릭만 별도 이벤트로 추가한다.
- 관리자 첫 화면 방문자 요약은 외부 API 비용·권한·캐시 정책을 정한 뒤 별도 계획으로 진행한다.

## 실제 결과

- `NEXT_PUBLIC_GA_MEASUREMENT_ID`와 `NEXT_PUBLIC_CLARITY_PROJECT_ID`가 설정된 배포 환경에서만 스크립트가 로드된다.
- 공개 페이지를 분석하고 관리자 페이지는 수집하지 않는다.
