# [완료] 페스티벌 관리 라인업 아티스트 추가 복구 계획

- 작성일: 2026-07-26
- 상태: 코드 구현 및 자동 검증 완료 · 실제 화면 확인 대기
- 승인일: 2026-07-26
- 대상: `/admin/festivals/[id]/lineup`
- DB 변경: 없음

## 목적과 완료 조건

- 기존 페스티벌의 라인업 관리 화면에서 아티스트를 검색해 공연 일정에 추가할 수 있게 한다.
- 추가한 아티스트는 기존 라인업 변경들과 함께 발표·정정 기록으로 한 번에 저장한다.
- 같은 아티스트를 같은 공연일에 중복 추가하지 못하게 한다.

## 확정 범위

1. 라인업 탭 상단에 기존 아티스트 검색 영역을 복구한다.
2. 검색 결과에 표시 이름, `normalized_name`, 별칭을 표시한다.
3. 검색 결과를 선택하면 공연일, 시작·종료 시간, 무대, 상태를 입력해 작업 목록에 추가한다.
4. 추가 직후에는 DB에 저장하지 않고 미저장 행으로 라인업 표에 표시한다.
5. 하단 `미저장 변경사항 전체 저장`을 눌렀을 때 기존 `apply_lineup_work_with_audit` RPC로 라인업과 감사 로그를 함께 저장한다.
6. 같은 아티스트 + 같은 공연일 조합의 중복을 화면에서 차단한다. 공연일이 다르면 같은 아티스트를 다시 추가할 수 있다.

## 제외 범위

- 이 화면에서 신규 아티스트 마스터를 생성하는 기능
- 아티스트 이름, `normalized_name`, 별칭 수정
- DB 스키마·RPC·RLS 변경

검색 결과가 없으면 아티스트 관리 페이지에서 먼저 신규 등록하도록 안내한다.

## 예상 수정 파일과 데이터 흐름

- `app/admin/festivals/[id]/lineup/components/ArtistAddSection.tsx`
  - 검색, 결과 선택, 일정 입력 UI 복구
- `app/admin/festivals/[id]/lineup/hooks/useFestivalArtists.ts`
  - 검색 상태와 임시 라인업 행 추가 로직 복구
- `app/admin/festivals/[id]/lineup/page.tsx`
  - 추가 영역 렌더링
- 관련 단위 테스트
- `PROJECT_STATUS.md`

데이터 흐름:

`아티스트 검색 → 기존 아티스트 선택 → 일정 입력 → 임시 행 추가 → 발표/정정 정보 입력 → 전체 저장 RPC → 라인업 및 감사 로그 저장`

## 작업 순서

1. 기존 `searchArtists`와 라인업 작업 타입을 재사용해 추가 상태를 구성한다.
2. `ArtistAddSection`을 현재 흰색 관리 화면 스타일로 만든다.
3. 선택 결과를 음수 임시 ID의 라인업 행으로 추가한다.
4. 중복 및 필수값 검증을 추가한다.
5. 저장 후 DB 라인업을 다시 불러오고 입력 상태를 초기화한다.
6. 테스트, 타입 검사, ESLint를 실행한다.
7. 계획과 `PROJECT_STATUS.md`에 실제 결과를 기록한다.

## 회귀 위험과 검증

- 기존 행 저장·삭제가 깨지지 않는지 확인한다.
- 같은 아티스트의 다른 공연일 추가는 허용되는지 확인한다.
- 같은 아티스트·같은 공연일 중복은 차단되는지 확인한다.
- 미저장 추가 행이 전체 저장 전 DB에 들어가지 않는지 확인한다.
- 전체 저장 후 새 행이 정상 ID로 다시 조회되고 감사 로그에 포함되는지 확인한다.
- 모바일과 PC에서 검색·선택·입력 UI가 겹치지 않는지 localhost에서 확인한다.

## 후속 개선점

- 검색 결과가 없을 때 현재 입력값을 넘겨 신규 아티스트 등록 화면을 여는 기능
- 신규 아티스트 등록 후 원래 페스티벌 라인업 화면으로 돌아오는 기능

## 실제 결과

- 기존 아티스트 이름·`normalized_name`·별칭 검색과 선택 UI를 복구했다.
- 공연일·시간·무대·상태를 입력한 뒤 음수 임시 ID의 미저장 행으로 추가한다.
- 같은 아티스트와 같은 공연일의 중복 추가를 차단하고, 다른 공연일은 허용한다.
- 임시 행은 기존 `apply_lineup_work_with_audit` 일괄 저장에 포함된다.
- 추가 후 공연일·무대는 연속 입력을 위해 유지하고 시작·종료 시간은 초기화한다.
- 관련 테스트 4건, 비증분 타입 검사, 변경 UI·로직 ESLint가 통과했다.
- 전체 테스트 135건 중 133건이 통과했고, 기존 티켓 테스트 2건은 쓰기 제한으로 임시 폴더를 만들지 못해 실행 실패했다.
- 브라우저 정책이 localhost 접근을 차단해 실제 화면 확인은 사용자가 수행해야 한다.
