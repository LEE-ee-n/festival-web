# [진행 중] SaaS 공개·유료화 준비

## 목적과 완료 조건

Festibom을 무료 공개 베타와 이후 유료 SaaS로 운영할 수 있도록 법무·개인정보·보안·장애 대응의 출시 차단 항목을 우선순위대로 해소한다.

완료 조건은 다음과 같다.

- 높은 등급의 운영 의존성 취약점이 제거되거나 영향과 완화 조치가 승인되어 있다.
- 관리자 MFA와 `aal2`, 일반 회원 간 RLS, 관리자·Bot RPC 권한을 운영 환경에서 검증한다.
- 실제 Google 로그인·개인 일정·페스티벌 기록에 맞는 개인정보처리방침과 이용약관을 게시한다.
- 회원이 직접 탈퇴할 수 있고 Auth와 개인 데이터가 정해진 정책대로 삭제된다.
- DB·Storage 백업과 복구, 개인정보 유출·장애 대응 절차를 실제로 시험한다.
- 포스터·로고·Instagram·티켓 출처의 이용 근거와 삭제 요청 처리 기준을 기록한다.
- 유료화 전 사업 형태, 결제·환불 정책과 B2C/B2B 대상을 사용자가 확정한다.

## 우선순위 원칙

1. 외부 결정 없이 지금 바로 코드와 운영 설정에서 줄일 수 있는 위험을 먼저 처리한다.
2. 개인정보 유출·관리자 탈취·복구 불능처럼 피해가 큰 항목을 디자인 개선보다 우선한다.
3. 무료 베타 공개에 필요한 범위와 유료 결제에 필요한 범위를 분리한다.
4. 법률 문구만 작성하지 않고 실제 데이터 처리·삭제·운영 절차와 일치시킨다.
5. 운영 설정과 DB는 파일 작성과 실제 적용·검증을 구분한다.

## 확정 범위와 제외 범위

### 1차: 즉시 착수 가능한 무료 베타 출시 차단 항목

- Next.js, PostCSS, Sharp, Nanoid 관련 보안 취약점 해소와 전체 회귀 검사
- Supabase Security Advisor 확인, 관리자 MFA 등록과 `aal2` 권한 강제
- 일반 회원 2계정 RLS, 비관리자 관리자 RPC, Bot 최소 권한 전수 검증
- CSP·HSTS를 포함한 HTTP 보안 헤더 적용과 GA4·Clarity·Storage 회귀 확인
- 실제 수집 데이터 목록과 보유 기간 확정, 개인정보처리방침·이용약관 정합성 수정
- 회원탈퇴, 개인 데이터 삭제, Auth 계정 삭제와 실패 시 원자성·재시도 처리
- DB·Storage 백업 범위, 복구 시험, RPO·RTO와 사고 대응 체크리스트 작성
- 운영 오류·권한 거부·관리자 로그인 이상 징후의 최소 모니터링과 알림

### 2차: 자료 조사 후 바로 정리 가능한 운영 항목

- 포스터·아티스트 로고·Instagram 이미지·티켓 데이터의 출처와 이용 근거 대장
- 권리자 삭제 요청, 오정보 제보, 개인정보 권리 요청의 접수·처리·완료 기록 절차
- Vercel·Supabase·Google·Microsoft의 국외 이전 국가·항목·방법·기간과 계약 자료 확인
- 비밀키·관리자·Bot 계정의 교체, 회수, 비상 세션 폐기 절차
- 의존성 자동 점검, 비밀정보 검사와 배포 전 보안 검사 자동화

### 3차: 사용자 결정 후 진행할 유료 SaaS 항목

- B2C 구독, B2B SaaS, 무료+광고·제휴 중 우선 사업 모델 결정
- 사업자등록, 통신판매업·부가통신사업 신고 대상 확인과 사업자 표시정보 준비
- 가격, VAT, 무료 체험, 자동갱신, 해지, 청약철회, 환불 정책 확정
- PG 선정과 주문·결제·구독·환불·Webhook·이용권 데이터 모델 설계
- B2B 선택 시 조직·워크스페이스·구성원·역할·`tenant_id` 격리, DPA·SLA·계약 구조 설계

### 제외 범위

- 사업 모델 확정 전 실제 결제 연동
- 사용자가 승인하지 않은 유료 요금제·환불률·SLA 수치 결정
- 변호사·세무사·개인정보 전문 자문을 받은 것으로 간주하는 법률 확정
- 이번 준비와 무관한 공개 화면 디자인 및 신규 축제 기능

## 작업 순서

### P0 — 무료 베타 공개 전 필수

1. [완료] 현재 `npm audit` 결과를 기준선으로 저장하고 Next.js·PostCSS·Sharp·Nanoid의 안전한 호환 버전을 확인한다.
2. [부분 완료] Next.js 16.3.0, PostCSS 8.5.26으로 업데이트해 운영·개발 의존성 감사를 0건으로 만들었다. 테스트 273개·타입 검사·ESLint 오류 0개와 사용자 환경 프로덕션 빌드 29개 경로 성공을 확인했다. Next.js 신규 탐색 경고 9개와 주요 PC·모바일 실제 화면 검증은 남아 있다.
3. [완료] Supabase Security Advisor와 전체 RLS·함수 실행 권한을 조회하고 위험 권한을 보강했다. 운영 DB 적용 후 경고는 56건에서 41건, 익명 실행 가능 `SECURITY DEFINER` 경고는 8건에서 0건으로 줄었다. 일반 회원 관리자 RPC 거부와 관리자·Bot 정상 권한도 확인했다.
4. [완료] 단일 관리자 TOTP MFA를 등록하고 공통 `is_admin()`에서 `aal2`를 강제했다. 운영 DB 역할 시험에서 관리자 `aal1`과 일반 회원 `aal2`는 거부되고 관리자 `aal2`만 허용됨을 확인했다.
5. [ ] CSP를 Report-Only로 먼저 적용해 위반 내역을 확인하고 GA4·Clarity·Supabase·이미지가 정상일 때 강제한다. HSTS와 나머지 헤더도 배포 환경에서 확인한다.
6. [ ] Google 로그인부터 개인 기록까지 실제 처리 항목·목적·보유 위치·기간·수탁자·국외 이전을 데이터 흐름표로 확정한다.
7. [ ] 개인정보처리방침의 “회원가입·개인 기록 없음” 문구를 제거하고 실제 처리 내용과 이용자 권리 절차를 반영한다.
8. [부분 완료] 최근 Google 재인증, 일반 회원 역할 재검사, 세션 폐기와 Auth Admin 삭제를 연결한 회원탈퇴 기능을 구현했다. Vercel 서버 비밀키 설정과 임시 회원 운영 E2E가 남아 있다.
9. [부분 완료] 운영 일반 회원 2계정으로 개인 테이블 9개와 RPC 2개의 양방향 교차 SELECT·INSERT·UPDATE·DELETE 거부를 확인했다. 탈퇴 후 데이터 소멸 E2E는 임시 회원 준비 후 진행한다.
10. [ ] DB와 Storage의 백업 범위를 확정하고 격리된 환경에서 복구 시험을 수행해 실제 RPO·RTO를 기록한다.

## 회귀 위험과 검증 방법

- 의존성 업데이트: Next.js 렌더링, 이미지 최적화, Server Action, 빌드 결과와 전체 자동 테스트를 비교한다.
- CSP: Report-Only에서 외부 도메인 목록을 수집하고 최소 허용 목록으로 강제한 뒤 로그인·분석·이미지를 확인한다.
- MFA: UI만 확인하지 않고 낮은 AAL 토큰으로 관리자 테이블과 RPC가 거부되는지 검증한다.
- RLS: 사용자 A가 사용자 B의 관심·일정·기록을 SELECT·INSERT·UPDATE·DELETE할 수 없는지 직접 시험한다.
- 탈퇴: 부분 삭제와 Auth만 삭제되는 불일치를 방지하고 실패·재시도·이미 탈퇴한 계정을 시험한다.
- 개인정보 문서: 코드·DB·외부 서비스의 실제 처리와 표의 각 항목을 대조하고 배포 화면과 시행일을 확인한다.
- 백업: 백업 파일 생성 성공이 아니라 새 환경 복원, 행 수·관계·Storage 파일 무결성까지 확인한다.
- 결제: 위조 Webhook, 재전송, 순서 역전, 결제 실패, 환불, 취소 후 재가입을 Sandbox에서 검증한다.
- tenant 격리: B2B 선택 시 모든 테이블·Storage 경로·RPC·감사 로그에 조직 경계가 적용되는지 확인한다.

## 승인 게이트

- P0의 각 코드·DB 변경은 기존 규칙대로 세부 구현 계획을 검토받은 뒤 진행한다.
- 개인정보처리방침 게시 전 운영자 표시정보, 실제 Supabase 리전과 외부 서비스 보유 기간을 사용자가 확인한다.
- 회원탈퇴 시 감사·보안 기록의 최소 보존 범위는 법적 근거 확인 후 사용자가 승인한다.
- 결제 구현 전 사업 모델, 판매 국가, 가격·환불 정책과 PG를 사용자가 결정한다.
- B2B tenant 구조는 B2B 판매를 선택한 경우에만 진행한다.

## 현재 확인 결과

- 최초 `npm audit --omit=dev`에서 Critical 0건, High 4개 패키지군을 확인했다.
- Next.js 16.3.0, ESLint Config Next 16.3.0, PostCSS 8.5.26으로 갱신했고 Sharp 0.35.3, Nanoid 3.3.18이 설치됐다.
- 갱신 후 운영 의존성과 개발 의존성 모두 `npm audit` 0건을 확인했다.
- 자동 테스트 273개와 TypeScript 검사는 통과했고 ESLint는 오류 0개·신규 경고 9개다.
- 사용자가 실제 환경에서 프로덕션 빌드의 컴파일, TypeScript, 페이지 데이터 수집과 정적 페이지 29개 생성을 모두 성공한 결과를 확인했다.
- 개인정보처리방침은 일반 회원가입·개인 기록이 없다는 과거 전제를 유지하고 있어 현재 기능과 불일치한다.
- 일반 회원 직접 탈퇴 기능을 구현했고 cascade FK 9개와 회원 소유 Storage 객체 0건을 확인했다. 운영 배포 비밀키 설정과 임시 회원 실제 탈퇴 검증은 남아 있다.
- 운영 일반 회원 2계정의 개인 테이블 9개·RPC 2개 교차 계정 RLS 시험이 통과했고 시험 데이터는 전부 rollback됐다.
- 기본 보안 헤더와 개인 테이블 RLS가 있으며 운영 Security Advisor와 두 일반 회원 간 교차 조회 거부를 확인했다. CSP·HSTS, 관리자 `aal2`, 개인 데이터 전체 쓰기 동작의 2계정 RLS 검증은 남아 있다.
- 수동 DB 백업 절차는 있으나 Storage 포함 복구 시험 결과는 확인되지 않았다.
- 베타 이용권은 있으나 실제 주문·결제·구독·환불 연동은 범위에서 제외돼 있다.
