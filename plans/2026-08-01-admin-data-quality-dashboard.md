# [구현 완료·화면 확인 대기] 관리자 데이터 점검판

## 목적과 완료 조건

- 관리자 메인 제목 아래에서 예정·진행 중 페스티벌의 누락 정보를 바로 확인한다.
- 누락 유형별 개수와 대상 페스티벌을 확인하고 기존 관리 화면으로 바로 이동한다.
- 점검판은 데이터를 자동 수정하거나 삭제하지 않는다.

## 확정 범위

- 관리자 메인의 기존 메뉴 카드 5개 아래에 `데이터 점검` 영역 추가
- 기본 대상은 종료·취소되지 않은 등록 페스티벌
- 점검 유형은 `공식 Instagram 없음`, `공식 홈페이지 없음`, `썸네일 없음`, `장소 또는 주소 없음`, `가격 구분 미정`
- 유형별 개수 표시와 선택 필터
- 선택한 유형에 해당하는 페스티벌명·기간·누락 항목 표시
- 각 행에서 `/admin/festivals/[id]/lineup` 관리 화면으로 이동
- 한 페스티벌이 여러 조건에 해당하면 각 누락 태그를 함께 표시
- 기존 관리자 인증과 `festivals` 읽기 권한 재사용, DB 변경 없음

## 제외 범위

- 데이터 자동 수정·자동 삭제
- 라인업 없음·티켓 없음 판정
- 종료·취소 축제의 과거 데이터 정비
- 아티스트 데이터 점검
- 이메일·Discord 알림
- 신규 테이블, RPC, migration

## 예상 수정 파일과 데이터 흐름

- `app/admin/page.tsx`: 기존 메뉴 카드 5개 아래에 점검 컴포넌트 배치
- `components/admin/AdminFestivalDataQuality.tsx`: 조회, 요약, 필터, 대상 목록 UI
- `lib/festivals/festivalDataQuality.ts`: 누락 조건과 유형별 집계 순수 함수
- `tests/festivalDataQuality.test.ts`: 복수 누락, 종료·취소 제외, 빈 문자열 판정 테스트
- `ARCHITECTURE.md`, `PROJECT_STATUS.md`: 구조와 진행 상태 기록

데이터 흐름은 관리자 메인 진입 → 기존 `festivals` 읽기 → 순수 함수로 누락 유형 계산 → 상단 요약·필터 목록 표시 → 기존 관리 화면 이동 순서다.

## 회귀 위험과 검증 방법

- 공백 문자열도 누락으로 판정하는지 테스트한다.
- `ended`, `cancelled` 축제가 기본 점검 수에 섞이지 않는지 확인한다.
- 같은 축제가 여러 유형에 중복 집계되더라도 목록 행은 한 번만 표시되는지 확인한다.
- 관리자 메인 기존 메뉴 링크와 인증 흐름이 유지되는지 확인한다.
- 모바일에서 요약 버튼과 대상 목록이 가로로 넘치지 않는지 실제 화면으로 확인한다.

## 후속 개선점

- 운영 기준이 정해지면 종료 축제 포함 필터를 추가할 수 있다.
- 라인업 발표 여부와 무료 행사 규칙을 데이터로 구분할 수 있게 되면 라인업·티켓 점검을 추가한다.
- 반복 누락을 자동 알림으로 보내는 기능은 별도 계획으로 검토한다.

## 구현 결과

- 기존 관리자 메뉴 5개 아래에 전체 확인 필요와 5개 누락 유형의 개수를 표시했다.
- 선택한 누락 유형으로 목록을 필터링하고, 한 페스티벌의 복수 누락 태그와 기존 관리 화면 링크를 표시한다.
- 종료·취소 축제는 제외하며 공백 문자열과 `unknown` 가격 유형도 누락으로 판정한다.
- 관련 테스트 4개와 전체 테스트 179개, 타입 검사와 변경 파일 ESLint가 통과했다.
- localhost PC·모바일 실제 화면 확인은 남아 있다.
