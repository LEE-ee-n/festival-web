# [완료] 2026-08-11 남은 검증 항목 일괄 점검

## 목적과 완료 조건

`PROJECT_STATUS.md`와 진행 중 계획에 남은 실제 화면·기능 검증을 중복 없이 묶어 실행하고, 근거가 확인된 항목만 완료 처리한다.

완료 조건:

- 최근 UI 변경의 PC·모바일 화면과 주요 상호작용 결과를 기록한다.
- 코드 구조 정리 후 아티스트·개인 기록·달력의 실제 동작을 확인한다.
- 베타 이용권의 관리자 부여·회수, 권한 유무별 조회·변경 차단을 확인한다.
- 테스트하지 못한 항목은 완료로 바꾸지 않고 필요한 계정·실데이터·배포 조건을 기록한다.
- 테스트용 데이터는 운영 데이터와 구분하고 검증 후 삭제한다.

## 확정 범위

### 1. 완료 처리할 최근 UI 검증

- 마이페이지 `내 공연 일정` 박스의 PC·모바일 정렬
- 일정 이미지 스티커 선택 후 다른 타임테이블 칸 클릭 시 선택 해제
- 시간 미정 라벨과 무대별 마지막 행 배치
- 2명 LINEUP의 선택·일반 카드 최대 높이
- 관련 화면의 브라우저 오류 유무

### 2. 관리자 아티스트 회귀

- 검색과 목록 필터
- 테스트 아티스트 생성
- 기본정보 수정과 새로고침 유지
- 테스트 아티스트 삭제
- 기존 운영 아티스트가 변경되지 않았는지 확인

이미지 업로드는 실제 Storage 객체 생성·삭제가 필요하므로 안전한 테스트 이미지가 준비된 경우에만 포함한다.

### 3. 개인 기록 회귀

- 베타 이용권이 있는 테스트 계정에서 일기 생성·조회·수정·삭제
- 페스티벌 기록 생성·상세 조회·삭제
- 테스트 기록이 모두 정리됐는지 확인

관리자 계정의 기존 기록은 수정하거나 삭제하지 않는다.

### 4. 달력·공개 화면 회귀

- PC 월 이동, 검색, 지역 필터, 상세 패널
- 모바일 폭에서 월 이동과 세로 스크롤
- 주요 공개 화면의 브라우저 오류 유무

### 5. 베타 이용권 회귀

- 관리자 가입자 목록, 가입 순번, 활성 인원 표시
- 테스트 회원 이용권 부여·회수
- 이용권 보유 시 개인 기능 실행
- 이용권 미보유·회수 후 기존 데이터 조회 유지와 신규 변경 차단
- 비관리자 관리자 화면·회원 목록 접근 거부

20명 정원 초과 검증은 운영 회원에게 임의로 권한을 부여하지 않고 DB transaction rollback 또는 별도 안전한 시험 방법이 있을 때만 수행한다.

## 제외·보류 범위

- 실제 수정할 축제가 필요한 기존 수정 최종 반영·감사 기록
- 실제 신규 축제 자료가 필요한 신규 등록 최종 승인
- 별도 임시 Google 계정이 필요한 회원탈퇴 E2E
- 배포 환경이 필요한 CSP·HSTS·GA4·Clarity 확인
- 격리 복구 환경이 필요한 DB·Storage 복구 시험
- 실제 Discord 게시물과 실행 Bot이 필요한 수집 회귀
- 기존 운영 데이터의 삭제 또는 의미 변경

이 항목들은 조건이 마련되지 않으면 미완료로 유지하고 필요한 준비물을 보고한다.

## 예상 수정 파일과 데이터 흐름

- `PROJECT_STATUS.md`: 실제 확인한 항목의 상태와 남은 검증 목록 갱신
- 직접 관련된 기존 `plans/*.md`: 화면 검증 결과와 미검증 사유 기록
- 이 계획 문서: 진행 항목 표시와 최종 결과 기록
- 테스트 데이터: UI 또는 안전한 DB 경로로 생성 → 동작 확인 → 삭제 → 잔존 여부 확인

기능 코드·DB 스키마·권한 정책은 변경하지 않는다. 테스트에서 결함이 발견되면 이번 작업에서 바로 수정하지 않고 별도 계획 대상으로 기록한다.

## 작업 순서

1. 최근 UI 검증 결과를 관련 계획과 현황판에 완료로 기록한다.
2. 관리자 아티스트 CRUD를 테스트 데이터로 확인하고 정리한다.
3. 현재 로그인 세션과 이용권 상태를 확인해 개인 기록 CRUD 가능 여부를 판단한다.
4. 달력·공개 화면의 PC·모바일 회귀를 확인한다.
5. 테스트용 일반 회원 계정이 준비돼 있으면 베타 이용권 부여·회수·차단을 확인한다.
6. DB 또는 화면에서 테스트 데이터가 남지 않았는지 확인한다.
7. 근거가 확인된 항목만 완료 처리하고 미완료 항목과 필요한 준비물을 보고한다.

## 회귀 위험과 검증 방법

- 운영 아티스트 삭제 위험: `[TEST]` 식별자를 사용하고 생성한 ID만 삭제한다.
- 개인 기록 손실 위험: 기존 기록을 수정하지 않고 신규 테스트 기록만 사용한다.
- 이용권 회수 영향: 사용자가 지정한 테스트 회원에게만 적용하고 원래 상태로 복구한다.
- 권한 오판 위험: 버튼 잠금뿐 아니라 실제 저장 실패와 기존 데이터 조회 유지까지 구분한다.
- 화면 오판 위험: PC·모바일 viewport와 DOM·브라우저 오류를 함께 확인한다.
- 문서 과완료 위험: 실제로 실행하지 못한 검증은 `대기` 상태를 유지한다.
