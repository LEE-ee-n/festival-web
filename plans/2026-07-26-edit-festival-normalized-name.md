# 신규 등록 작업함 축제 normalized_name 직접 수정

상태: 코드 구현 완료 · localhost 직접 입력 확인 대기

## 목적과 완료 조건

- 신규 페스티벌 등록 작업함에서 축제 `normalized_name`을 직접 수정할 수 있게 한다.
- JSON에 `normalized_name`이 없어도 빈 입력칸에서 관리자가 직접 새 값을 작성할 수 있게 한다.
- 기존 값은 전체 삭제 후 새 값으로 교체할 수 있게 한다.
- 입력 도중 문자가 자동으로 삭제되지 않게 한다.
- 올바르지 않은 값은 그대로 보여주되 저장·승인 전에 명확한 오류를 표시한다.
- 직접 작성한 올바른 값은 저장·탭 이동·다른 작업 선택 후 복귀해도 그대로 유지한다.

## 확인된 원인

- 현재 입력할 때마다 `normalizeFestivalName` 전체 규칙을 실행한다.
- 이 함수가 `20XX`, `festival`, 한글·공백·기호를 즉시 제거해 입력값이 사라진다.
- 화면의 연도 포함 경고도 입력 단계에서 연도가 먼저 삭제되므로 사실상 작동할 수 없다.

## 확정 제안 범위

- JSON 불러오기 여부와 관계없이 `normalized_name` 입력창을 항상 직접 편집 가능하게 유지한다.
- 입력 중에는 NFKC 변환과 영문 소문자 변환만 적용하고 문자를 삭제하지 않는다.
- `^[a-z0-9]+$` 형식이 아니면 입력창 아래에 즉시 오류를 표시한다.
- 형식이 잘못된 동안 저장·다음 단계·승인을 차단하고 해당 입력칸으로 이동한다.
- 올바른 값을 입력하면 기존 중복 확인을 다시 실행한다.
- 유효한 수동 입력값을 저장할 때 전체 정규화 함수가 다시 덮어쓰지 않게 한다.
- DB의 `normalized_name` 형식과 중복 판별 규칙은 변경하지 않는다.

## 검증

- JSON에 값이 없는 상태에서 빈칸부터 직접 작성할 수 있어야 한다.
- 기존 값을 전체 삭제한 뒤 영문 소문자와 숫자를 다시 입력할 수 있어야 한다.
- 한글·공백·기호는 화면에서 사라지지 않고 형식 오류로 표시되어야 한다.
- 잘못된 값으로 저장·승인할 수 없어야 한다.
- 직접 작성한 유효한 값이 저장 후 다시 열었을 때 동일해야 한다.
- 올바른 값으로 중복 확인과 다음 단계 이동이 가능해야 한다.
- 관련 단위 테스트, ESLint와 TypeScript 검사를 통과한다.

## 후속 개선점

- `festival` 단어와 연도 포함 여부를 오류로 막을지 별도 결정한다.
