# [추가 수정 완료·실기기 재확인 대기] 모바일 캘린더 스와이프 제스처 개선

## 목적과 완료 조건

- 모바일에서 캘린더 위를 위아래로 움직여도 페이지가 자연스럽게 스크롤된다.
- 좌우 스와이프 의도가 확인되면 세로 이동보다 월 전환을 우선한다.
- 취소된 터치와 빠른 연속 스와이프에서도 제스처 상태와 이동 월이 꼬이지 않는다.
- 모바일 당겨서 새로고침 이후에도 다음 좌우 스와이프가 정상 작동한다.
- 터치 로직을 캘린더 화면 코드와 분리해 기준값을 안전하게 조정하고 테스트할 수 있게 한다.

## 확정 범위

- `CalendarGrid`의 `touch-pan-y`를 유지해 세로 페이지 스크롤 허용
- 최초 약 10px 이동 후 가로·세로 의도 잠금
- 가로 이동량이 세로 이동량의 110% 이상일 때 좌우 제스처로 판정
- 가로 이동 45px 이상에서 한 달 이동
- `pointercancel` 발생 시 저장된 좌표와 방향 상태 초기화
- 포인터 시작 즉시 캡처하지 않고 가로 방향이 확정된 순간에만 캡처
- `lostpointercapture`, `visibilitychange`, `pageshow`에서 남은 제스처 상태 초기화
- URL 반영 전 연속 스와이프도 마지막 요청 월을 기준으로 계산
- UI 컴포넌트 추가 없이 캘린더 전용 훅과 순수 판정 함수로 분리

## 제외 범위

- 달력 디자인, 셀 높이, 축제 막대와 날짜 선택 동작 변경
- PC 마우스 휠 월 이동 기준 변경
- 스와이프 애니메이션 추가
- URL의 `year`, `month` 형식 변경

## 예상 수정 파일·구조

- `components/calendar/useCalendarSwipe.ts`: 포인터 시작·이동·종료·취소·캡처 상실과 페이지 생명주기 상태 관리
- `lib/calendarSwipe.ts`: 이동 거리, 방향 비율과 최소 거리로 좌우 스와이프 판정
- `components/calendar/CalendarGrid.tsx`: 훅에서 받은 포인터 이벤트 연결
- `components/Calendar.tsx`: 훅 사용과 URL 반영 전 월 커서 즉시 갱신
- `tests/calendarSwipe.test.ts`: 가로·세로·대각선·임계값 판정 검증
- `tests/calendarSelection.test.ts`: 연말·연초 및 연속 월 이동 계산 검증
- `ARCHITECTURE.md`, `PROJECT_STATUS.md`: 구조와 검증 상태 기록

데이터 흐름은 `CalendarGrid` 포인터 이벤트 → `useCalendarSwipe` 방향 잠금 → `calendarSwipe` 최종 판정 → `Calendar` 월 이동 콜백 → URL 동기화 순서다.

## 회귀 위험과 검증 방법

- 대각선 세로 스크롤이 월 전환으로 오인되지 않는지 방향 비율 테스트와 실제 모바일로 확인한다.
- 당겨서 새로고침이 캘린더 포인터 캡처와 충돌하지 않는지 실제 모바일에서 확인한다.
- 짧은 탭과 날짜 선택이 스와이프로 오인되지 않는지 45px 임계값을 테스트한다.
- 스크롤 중 `pointercancel` 이후 다음 스와이프가 정상인지 확인한다.
- 빠르게 두 번 넘겼을 때 같은 달을 반복 요청하지 않고 두 달 이동하는지 확인한다.
- 이전·다음 달 버튼, 오늘 버튼, 브라우저 뒤로가기와 URL 직접 접근이 유지되는지 확인한다.

## 후속 개선점

- 실제 기기 사용감에 따라 방향 비율 110%와 거리 45px는 별도 승인 후 조정한다.

## 구현 결과

- `useCalendarSwipe` 훅으로 포인터 시작·이동·종료·취소와 방향 잠금 상태를 분리했다.
- 10px 이후 한 축이 다른 축보다 110% 이상 우세할 때만 방향을 잠그고, 가로 45px 이상에서 월을 이동한다.
- `pointercancel`에서 제스처 상태를 초기화해 세로 스크롤 이후 다음 좌우 스와이프가 영향을 받지 않게 했다.
- URL 반영 전에도 별도 월 커서를 즉시 갱신해 빠른 연속 스와이프가 같은 달을 반복 요청하지 않게 했다.
- 최초 구현 당시 관련 테스트와 전체 테스트 173개, 타입 검사와 변경 파일 ESLint가 통과했다.
- 실제 모바일 화면 확인은 남아 있다.
- 실제 확인에서 당겨서 새로고침 후 좌우 스와이프가 작동하지 않는 문제가 재현됐다.
- 추가 수정으로 포인터 시작 시 캡처를 제거하고 가로 방향 확정 후에만 캡처하도록 변경했다.
- `pointercancel`, `lostpointercapture`, `visibilitychange`, `pageshow`와 컴포넌트 해제 시 좌표·방향·캡처 상태를 초기화한다.
- 관련 테스트 14개, 전체 테스트 174개, 타입 검사와 변경 파일 ESLint가 통과했으며 실제 모바일 재확인이 남아 있다.
