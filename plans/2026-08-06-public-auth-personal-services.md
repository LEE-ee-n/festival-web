# [진행 중] 2026-08-06 공개 사용자 로그인·개인 일정 MVP 계획

## 목표

관리자 로그인과 분리하지 않고 Supabase Auth를 재사용해 공개 사용자가 좋아하는 아티스트와 관람할 공연을 저장하고, 다녀온 페스티벌에서 좋았거나 아쉬웠던 아티스트의 기억을 기존 페스티벌 데이터 위에 개인 아카이브로 남길 수 있게 한다.

최종 핵심 경험은 사용자가 예전에 다녀온 페스티벌을 다시 열어보고 “이때 누구를 봤었지?”, “이 노래를 들었었지”, “이때 좋았는데”를 떠올리는 것이다.

## 1차 범위

- Google OAuth 로그인·로그아웃
- 헤더 로그인 상태 표시
- 관심 아티스트 저장·해제
- 진행 중인 페스티벌 상세에서 공연 선택·해제
- 선택한 공연을 `/mypage`에서 날짜·시간순으로 확인
- 선택한 공연 목록을 휴대폰 배경화면 PNG로 생성·다운로드

## 제외 범위

- Google 외 소셜 로그인
- 이메일·비밀번호 회원가입과 비밀번호 재설정
- 푸시·이메일 알림
- 개인 캘린더와 일정 알림
- 관리자 권한 변경

## 2차 개인 기록 범위

- 기존 `festivals`, `festival_artists`, `artists`를 복제하지 않고 사용자 기록에서 참조한다.
- 마이페이지에 최근 페스티벌 기록 가로 슬라이더, `기록 추가`, `전체보기`를 제공한다.
- 전체보기 `/mypage/festival-records`에서 사용자가 기록한 모든 페스티벌을 썸네일 카드로 표시한다.
- 작성 `/mypage/festival-records/new`에서 종료·진행 중 페스티벌, 복수 참여 날짜, 한줄 기록과 기록하고 싶은 아티스트를 선택한다.
- 상세 `/mypage/festival-records/[id]`는 대표사진·연도·장소·한줄 기록과 실제 관람 공연만 시간순으로 보여주는 추억 다시보기 화면으로 만든다.
- 수정 `/mypage/festival-records/[id]/edit`는 같은 공용 폼을 재사용하며 상세 상단에서 진입한다.
- 사용자당 페스티벌 기록은 하나로 유지하고, 실제 관람 공연은 기존 `festival_artists.id`를 참조한다.
- 곡·공연 메모·평점·외부 미디어 메타데이터를 공연 기록 아래에 확장 가능한 별도 테이블로 분리한다.
- 미디어 파일 자체는 Supabase Storage에 저장하지 않고 provider·external file ID·preview URL·file type만 저장한다.
- 다른 사용자의 기록은 조회·수정·삭제할 수 없도록 모든 개인 테이블에 본인 전용 RLS를 적용한다.
- 페스티벌 상세의 큰 작성 폼은 제거하고 필요하면 기록 작성 페이지로 가는 가벼운 링크만 남긴다.
- MVP는 기능 흐름을 우선하고 세부 디자인은 실제 사용 후 별도 수정한다.

### 개인 기록 데이터 관계

- `user_festival_diaries` → 기존 `festivals.id`
- `user_festival_performances` → 기록 ID + 기존 `festival_artists.id`
- `user_festival_songs` → 사용자 공연 기록 ID
- `user_festival_media` → 사용자 공연 기록 ID + 외부 파일 메타데이터

### 개인 기록 MVP 제외 범위

- Google Drive·OneDrive API와 실제 파일 업로드
- 자동 세트리스트 수집
- 검색·연도/아티스트 필터·통계·지도·Wrapped
- 친구·공유·공개 프로필

## 데이터베이스

새 migration에서 다음 테이블을 추가한다.

- `user_favorite_artists(user_id, artist_id, created_at)`
- `user_schedule_items(user_id, festival_artist_id, created_at)`

관심 아티스트와 일정 항목은 `(user_id, 대상 ID)` 복합 기본 키, 대상 삭제 시 cascade, 사용자 본인만 select/insert/delete 가능한 RLS를 사용한다. 공개 축제·아티스트 조회 정책은 변경하지 않는다.

## 구현 규칙

- 기존 `profiles`와 관리자 `role`은 그대로 유지한다.
- 관리자 역할은 기존 운영자 1명만 허용하고 일반 회원은 관리자 역할을 생성·수정할 수 없다.
- 공개 사용자는 Google OAuth만 제공하고 관리자 이메일·비밀번호 로그인은 기존 화면에 유지한다.
- 추후 Kakao 로그인을 우선 검토하고, Naver는 별도 OAuth 연동 범위로 분리한다.
- 공개 로그인 사용자를 관리자 레이아웃으로 보내지 않는다.
- 로그인하지 않은 상태에서 관심·공연 선택 버튼을 누르면 로그인 페이지로 이동시키고 원래 경로를 보존한다.
- 관심 버튼은 서버 렌더링 결과와 클라이언트 상태가 어긋나지 않게 현재 세션 기준으로 표시한다.
- 중복 저장은 DB 기본 키와 UI 상태 양쪽에서 차단한다.
- 공연 선택은 공연 시간이 있는 공개 출연 항목만 허용하고, 종료된 페스티벌에서는 새 선택을 막는다.
- 배경화면은 서버에 저장하지 않고 브라우저에서 PNG로 생성한다. 기본 크기는 1080×2400으로 한다.
- 모든 쓰기 작업은 Supabase RLS를 통과해야 하며 service role 키를 브라우저에 노출하지 않는다.
- OAuth Client Secret과 Google provider token은 애플리케이션 코드·로그·DB에 저장하지 않는다.
- 운영·localhost 외 OAuth redirect URL은 허용하지 않는다.
- 공개 예정·진행 중 축제의 시간이 확정된 공연만 개인 일정에 추가할 수 있다.
- 기능별 데이터 함수, 상태 훅, 공통 표시 컴포넌트, 페이지 전용 연결 컴포넌트를 분리하며 페이지에 인증·DB 로직을 직접 몰아넣지 않는다.

- 기본 기록 저장 버튼을 `다음`으로 변경하고 선택한 아티스트를 날짜·시간순 카드 목차로 작성하는 2단계 화면을 구현했다.
- 아티스트 카드는 한 번에 하나를 펼쳐 `봤어요`, `잠깐 봤어요`, `못 봐서 아쉬워요` 중 상태를 선택하고 글·곡·평점을 저장하도록 구현했다.
- 사진·영상 입력 UI는 제외했으며 추후 Google Drive 등 외부 저장소 연동 시 별도 추가하도록 유지했다.
- 아티스트 기록 단계 구현 후 TypeScript, 관련 ESLint, diff 검사와 전체 테스트 237개가 통과했다.
- 실제 계정에서 아티스트 상태·글·곡·평점 저장과 수정이 정상 동작하고 기록 상세에 반영되는 것을 확인했다.
- 작성한 아티스트와 미작성 아티스트가 날짜·시간순 카드 목록에 함께 유지되는 것을 확인했다.
- 작성 내용이 있는 아티스트는 기본 수정 목록에 `작성한 기록 있음`으로 표시하고, 선택 해제 시 다음 저장에서 DB 기록이 삭제된다는 확인창을 추가했다.
- 선택 해제만으로 즉시 삭제하지 않고 `다음` 저장 시 확정 삭제해, 저장 전 다시 선택하면 기존 기록을 보존하도록 했다.
- 실제 계정에서 작성 기록이 있는 아티스트 선택 해제, 다른 아티스트 신규 선택과 다음 단계 저장 결과가 DB와 화면에 정상 반영되는 것을 확인했다.
- PC·모바일 공용 페스티벌 선택 검색 컴포넌트를 추가하고 메인 공개 검색과 같은 문자 정규화 규칙을 재사용했다.
- `다음`이 비활성화됐을 때 페스티벌·참여 날짜·한줄 기록 중 빠진 항목을 버튼 아래에 구체적으로 안내하도록 개선했다.
- 공용 타임테이블에서 좋아하는 아티스트 이름 바로 뒤에 클릭 기능 없는 빨간 하트 SVG를 표시하도록 구현했다.
- 일정 선택 버튼의 문구·테두리·배경을 제거하고 캘린더 SVG만 표시하며 선택 상태는 파란색 아이콘으로 구분하도록 변경했다.
- 메인 달력 상세 패널, 독립 페스티벌 상세페이지와 타임테이블 미공개 출연진 목록에 같은 관심 표시를 적용했다.
- 관심 표시와 일정 아이콘 변경 후 TypeScript, 관련 ESLint, diff 검사와 전체 테스트 237개가 통과했다.
- 실제 화면에서 좋아하는 아티스트의 빨간 하트 표시와 내 공연 일정의 캘린더 선택 상태가 정상 출력되는 것을 확인했다.
- 공연 일정 추가·삭제 후 캘린더 아이콘 상태가 즉시 정상 반영되는 것을 확인했다.
- 메인 달력 상세 패널 제목을 가장 진한 ink 색상과 작은 화살표가 있는 독립 상세페이지 링크로 변경했다.
- 타임테이블 날짜의 검은 버튼형 배경과 둥근 모서리를 제거하고 `CalendarDays` SVG·진한 ink 글자·내용 너비 밑줄로 변경했다.
- 날짜 구역의 기존 안쪽 여백은 유지해 일정 구역 사이의 구분감을 보존했다.
- 제목 링크와 날짜 제목 변경 후 TypeScript, 관련 ESLint와 diff 검사가 통과했다.

## 완료 조건

- 비로그인 사용자는 공개 페이지를 그대로 볼 수 있다.
- 로그인 사용자는 아티스트와 공연을 저장하고 새로고침 후에도 유지된다.
- 선택한 공연을 휴대폰 배경화면 PNG로 다운로드할 수 있다.
- 사용자가 기록한 페스티벌을 마이페이지와 전체보기에서 다시 찾을 수 있다.
- 개인 기록 상세에는 사용자가 기록 대상으로 선택한 아티스트를 공연 날짜별·시간순으로 표시한다.
- 개인 기록의 페스티벌·공연·아티스트 정보는 기존 운영 데이터를 참조하고 복제하지 않는다.
- 외부 미디어는 파일이 아니라 연결 메타데이터만 개인 DB에 저장한다.
- 다른 사용자의 관심 데이터는 조회·변경할 수 없다.
- 관리자 로그인과 관리자 페이지 접근이 기존처럼 동작한다.
- 전체 테스트, TypeScript, 관련 ESLint가 통과한다.
- Supabase Security Advisor 결과를 확인하고 로그인 관련 경고를 처리한다.
- 서로 다른 일반 회원 계정 2개로 상대방의 관심·일정 조회·삭제가 차단되는지 실제 검증한다.
- 단일 관리자 계정에 MFA를 적용한다.
- 로그인 서비스에 맞게 개인정보처리방침을 수정하고 회원탈퇴 기능을 제공한다.
- 운영 DB에서 `authenticated`가 실행할 수 있는 RPC를 전수 점검하고 관리자 전용 RPC의 권한 검사를 확인한다.

위 보안·개인정보 항목까지 모두 통과하기 전에는 로그인 기능을 `[완료]`로 표시하지 않는다.
