# 신규 페스티벌 미완성 초안 조회 허용 계획

- 작성일: 2026-07-24
- 상태: 구현 완료·화면 확인 대기
- 승인일: 2026-07-24
- 대상: `/admin/festival-candidates` 신규 페스티벌 작업함의 초안 조회·임시저장 검증
- DB 변경: 없음

## 목적

- 날짜 등 필수정보가 아직 비어 있는 후보도 신규 작업함 목록과 편집 화면에 표시한다.
- 조회·임시저장용 구조 검증과 단계 이동·최종 등록용 필수값 검증을 분리한다.
- 후보 한 건이 미완성이라는 이유로 다른 정상 후보까지 화면에서 보이지 않는 문제를 해결한다.

## 확정 범위

1. 조회·편집용 초안 파서를 추가해 객체·배열 등 기본 구조는 확인하되 축제 이름·`normalized_name`·시작일·종료일의 빈 값을 허용한다.
2. `festival_candidates` DB 행을 화면 데이터로 변환할 때 조회·편집용 파서를 사용한다.
3. 신규 후보 임시저장 시에도 조회·편집용 파서를 사용해 필수정보가 덜 입력된 상태를 저장할 수 있게 한다.
4. 기존 단계 이동 검증과 `validateFestivalDraftForApproval`은 유지해 페스티벌 정보 단계 이후와 최종 등록에서 유효한 이름·`normalized_name`·시작일·종료일을 계속 요구한다.
5. 날짜가 없는 후보와 정상 후보가 함께 있어도 두 후보 모두 개별적으로 파싱되는 회귀 테스트를 추가한다.
6. 실제 동작에 맞게 `FESTIVAL_INGESTION_FLOW.md`와 `PROJECT_STATUS.md`를 갱신한다.

## 유지할 규칙

- DB에 저장된 기존 후보 데이터는 수정하거나 삭제하지 않는다.
- 신규 등록과 기존 페스티벌 업데이트 흐름을 섞지 않는다.
- 날짜가 비어 있거나 잘못된 후보를 자동 보정하지 않는다.
- 축제 식별과 최종 등록에는 유효한 `normalized_name`, 시작일, 종료일을 계속 요구한다.
- 잘못된 최상위 JSON, `festival` 객체 누락, 잘못된 `artists`·`tickets` 구조는 조회·편집용 파서에서도 오류로 처리한다.

## 예외 상황·회귀 위험

- 날짜뿐 아니라 직접 작성 초안의 빈 축제명과 빈 `normalized_name`도 조회 단계에서는 허용해야 한다.
- 느슨한 파서가 최종 승인 RPC 직전까지 사용되면 불완전한 데이터가 운영 테이블에 반영될 위험이 있으므로 최종 승인 검증 연결을 테스트로 고정한다.
- 한 후보의 첨부자료 형식 등 날짜와 무관한 손상까지 무시하지 않고 기존 오류 처리를 유지한다.

## 검증 항목

- 날짜가 빈 초안을 조회·편집용 파서가 읽는다.
- 날짜가 빈 초안을 엄격한 파서 또는 최종 승인 검증이 거부한다.
- 정상 후보와 날짜 누락 후보가 함께 있어도 각각 화면 데이터로 변환된다.
- 날짜 입력 전 임시저장은 가능하다.
- 페스티벌 정보 단계 이후 이동과 최종 등록은 날짜 누락 시 차단된다.
- 관련 단위 테스트와 전체 테스트 통과
- `npm run typecheck` 통과
- 변경 파일 ESLint 통과
- localhost에서 기존 후보 목록과 날짜 누락 후보가 함께 표시됨

## 완료 조건

- 날짜 누락 후보 때문에 신규 작업함 전체가 빈 목록으로 보이지 않는다.
- 기존 후보 데이터의 삭제·일괄 수정 없이 화면에서 다시 접근할 수 있다.
- 최종 등록의 필수 날짜 검증은 유지된다.
- 테스트·타입·린트·화면 검증 결과가 문서에 기록된다.
