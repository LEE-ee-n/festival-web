# [구현 완료·화면 확인 대기] 캘린더 축제 막대 파스텔 팔레트 전환

## 목적과 완료 조건

- 캘린더에서 축제별로 이어지는 5색 막대를 지정한 파스텔 팔레트로 전면 교체한다.
- 같은 축제를 나타내는 축제 카드의 세로 색상선도 동일한 팔레트를 사용한다.
- 파스텔 배경에서도 축제명이 선명하게 읽혀야 한다.

## 확정 범위

- 축제 식별용 색상 순서를 아래와 같이 적용한다.
  1. `#FFC8D4`
  2. `#C0E6F4`
  3. `#DEF4C5`
  4. `#DCC2EE`
  5. `#FFCFB5`
- 캘린더 축제 막대와 축제 카드 세로 색상선에 동일한 ID 기반 색상 규칙 적용
- 중복된 색상 배열과 선택 함수를 공통 모듈로 통합
- 캘린더 막대 축제명은 파스텔 배경에 맞춰 진한 글자색으로 변경

## 제외 범위

- 토요일·일요일 날짜 글자색
- 상세 페이지 시간·배지, 카테고리 등 기존 `festival-*` 전역 색상
- 관리자 화면과 로고·파비콘
- 선택 날짜의 파란 테두리와 셀 hover 색상

## 예상 수정 파일

- `tailwind.config.ts`
- `lib/festivalColor.ts` 또는 같은 목적의 공통 모듈
- `components/Calendar.tsx`
- `components/FestivalCard.tsx`
- `components/calendar/CalendarDayCell.tsx`
- 관련 테스트
- `PROJECT_STATUS.md`

## 작업 순서

1. 파스텔 5색을 축제 식별 전용 Tailwind 색상으로 등록한다.
2. 색상 배열과 축제 ID 기반 선택 함수를 공통 모듈로 이동한다.
3. 캘린더 막대와 축제 카드가 공통 함수를 사용하도록 변경한다.
4. 캘린더 막대 글자와 점을 진한 색으로 조정한다.
5. 단위 테스트, 타입 검사, ESLint를 실행하고 localhost 화면을 확인한다.

## 회귀 위험과 검증 방법

- 축제 ID별 색상 선택이 기존처럼 항상 일정한지 단위 테스트로 확인한다.
- 여러 날짜에 걸친 막대의 모든 조각이 같은 색인지 기존 달력 테스트로 확인한다.
- 밝은 파스텔 위 글자가 실제 PC·모바일 화면에서 읽히는지 확인한다.
- 전역 브랜드 색상을 유지해 주말·상세 페이지가 의도치 않게 바뀌지 않는지 검색한다.

## 후속 개선점

- 선택 날짜 테두리와 hover 색상도 파스텔 계열로 바꾸려면 별도 범위로 결정한다.

## 구현 결과

- 지정한 5개 색상 코드는 `tailwind.config.ts`에 `festival-bar-*` 이름으로만 정의했다.
- 컴포넌트에서는 색상 코드를 직접 사용하지 않고 명명된 Tailwind 클래스만 사용한다.
- 캘린더 축제 막대와 축제 카드 세로 색상선이 공통 `getFestivalColorClass` 함수를 사용하도록 중복을 제거했다.
- 파스텔 배경의 캘린더 축제명과 표시점은 진한 `ink-secondary` 계열로 변경했다.
- 전체 테스트 162개, 타입 검사와 변경 파일 ESLint가 통과했다.
- 프로덕션 빌드는 코드 컴파일과 TypeScript 검사까지 통과했고, 생성 CSS에서 5개 `festival-bar-*` 클래스와 정확한 RGB 값을 확인했다. 정적 페이지 생성 단계만 현재 실행 권한상 `.env.local`을 읽을 수 없어 중단됐다.
- localhost 실제 화면 확인은 브라우저 정책상 접근이 차단되어 남아 있다.
