# 2026-08-11 Android 하이브리드 앱 1차 개발

## 목적과 완료 조건

기존 `festibom.com`을 유지하면서 Expo·React Native WebView 기반 Android 앱을 추가한다. 네이티브 하단 메뉴, Google OAuth 딥링크, 관심 기반 푸시, 일정 이미지 저장·공유가 동작하고 기존 베타 이용자 약 20명이 비공개 테스트할 수 있는 상태를 완료 조건으로 한다.

## 확정 범위와 제외 범위

- Android 앱 ID `com.festibom.app`, 앱 이름 `Festibom`, 딥링크 `festibom://`을 사용한다.
- 홈·축제·아티스트·마이페이지 네이티브 하단 메뉴와 공개·회원 웹 화면만 앱에 제공한다.
- Google 로그인은 시스템 브라우저와 Supabase OAuth 콜백으로 처리한다.
- 기존 `user_favorite_festivals`를 관심 축제 단일 원본으로 사용하고 알림 설정, 앱 기기, 알림 이벤트·발송 기록을 RLS로 보호한다.
- 좋아하는 아티스트 출연, 관심 축제 라인업·시간표, 티켓 하루 전·10분 전 알림을 제공한다.
- 관리자, 결제, iOS, Play 공개 출시는 제외한다.

## 예상 수정 영역과 데이터 흐름

- `mobile/`: Expo 앱, WebView 셸, 하단 메뉴, 딥링크, 푸시, 이미지 공유
- `lib/mobile/`, 공개·마이페이지 컴포넌트: 검증된 웹–앱 메시지, 앱 전용 UI, 관심 축제와 알림 설정
- `supabase/migrations/`, `supabase/functions/`: 신규 테이블·RLS·알림 큐와 Expo 발송

관리자 데이터 반영 → 알림 이벤트 묶음 → 관심 관계·설정 조회 → 활성 기기 발송 → 발송 결과 기록 → 알림 딥링크로 축제 상세 이동.

## 작업 순서

1. 계획·도메인·ADR과 상태 문서를 반영한다.
2. 관심 축제·기기·설정·이벤트·발송 DB와 RLS·인덱스를 구현한다.
3. 웹–앱 브리지, 앱 전용 UI, 관심 축제·알림 설정을 구현한다.
4. Expo WebView 앱, 네이티브 메뉴·뒤로가기·외부 링크·오프라인 화면을 구현한다.
5. Google OAuth 딥링크, 이미지 저장·공유, 푸시 등록·딥링크를 연결한다.
6. 알림 집계·예약·중복 방지·영구 실패 비활성화를 구현한다.
7. 자동 테스트, 운영 DB 적용, localhost·Android 실기기·Play 비공개 테스트를 검증한다.

## 회귀 위험과 검증 방법

- 일반 웹 회귀: 앱 감지는 UI에만 사용하고 전체 웹 테스트·빌드와 브라우저 화면을 확인한다.
- OAuth 세션 손실: 로그인·재실행·로그아웃·회원탈퇴와 기존 RLS를 실기기에서 확인한다.
- 알림 중복: 회원·축제·종류·기준 시각 중복키와 예약 재계산 테스트를 실행한다.
- 권한 우회: 다른 회원의 관심·기기·설정 접근 거부와 베타 이용권 쓰기 제한을 검증한다.
