# [완료] 기존 페스티벌 수정 원본 정보 표시 계획

- 작성일: 2026-07-26
- 상태: 코드 구현 및 자동 검증 완료 · 실제 화면 확인 대기
- 승인일: 2026-07-26
- 대상: `/admin/festivals/import-json?festivalId=...&updateDraftId=...`
- DB 변경: 없음

## 목적과 완료 조건

- 기존 페스티벌 수정 검토를 시작하기 전에 수집 원본을 확인할 수 있게 한다.
- 신규 페스티벌 등록 화면과 같은 구성으로 원본 출처, OCR 수집 원문, 첨부 자료를 표시한다.

## 확정 범위

- 수정 화면 제목·임시저장 버튼 아래, 5단계 진행 표시 위에 원본 정보 영역을 넣는다.
- `draft.candidate.source_url` 또는 수정 초안의 `source_url`로 `원본 출처 열기`를 표시한다.
- `draft.candidate.raw_text`가 있으면 접을 수 있는 `수집 원문 보기`를 표시한다.
- `draft.candidate.source_assets`가 있으면 첨부 자료를 표시한다.
- Storage의 `storage_path`만 있는 이미지는 신규 등록과 동일하게 임시 URL을 생성해 열 수 있게 한다.

## 제외 범위

- JSON 전체 내용 표시
- OCR 재실행
- 사진별 OCR 출처 구분
- DB·Bot·RLS 변경

## 예상 수정 파일

- 원본 정보 공통 컴포넌트
- `app/admin/festival-candidates/page.tsx`
- `app/admin/festivals/import-json/StagedFestivalUpdate.tsx`
- 관련 테스트
- `PROJECT_STATUS.md`

## 작업 순서

1. 신규 등록 화면의 원본 정보 UI를 공통 컴포넌트로 분리한다.
2. 신규 등록 화면을 공통 컴포넌트로 교체해 기존 동작을 유지한다.
3. 기존 수정 초안의 첨부 자료에 필요한 임시 URL을 생성한다.
4. 수정 화면 제목 아래·단계 표시 위에 공통 컴포넌트를 배치한다.
5. 타입 검사, ESLint, 관련 테스트를 실행한다.

## 회귀 위험과 검증

- 신규 등록 화면의 원본 출처·원문·첨부 자료가 기존처럼 표시되는지 확인한다.
- 원문이나 첨부 자료가 없는 초안에서는 빈 영역이 생기지 않는지 확인한다.
- 기존 수정 화면에서 원본 정보가 단계 표시 위에 나타나는지 확인한다.
- Storage 경로가 외부에 그대로 노출되지 않고 임시 URL로 열리는지 확인한다.

## 후속 개선점

- 필요할 경우 별도 계획으로 JSON 전체 보기와 사진별 OCR 근거 저장을 검토한다.

## 실제 결과

- 신규 등록 화면의 원본 출처·수집 원문·첨부 자료 UI를 `CandidateSourcePreview` 공통 컴포넌트로 분리했다.
- 기존 페스티벌 수정 화면의 제목·임시저장 버튼 아래, 5단계 표시 위에 같은 컴포넌트를 배치했다.
- 수정 초안의 `draft_json.candidate.raw_text`를 OCR 수집 원문으로 표시한다.
- `source_assets`에 Storage 경로만 있으면 1시간 유효한 임시 URL을 만들어 첨부 자료로 연다.
- 원본 데이터가 전혀 없으면 영역과 여백을 모두 표시하지 않는다.
- 비증분 타입 검사와 변경 파일 ESLint가 통과했다.
- 관련 JSON·축제 초안 테스트 23건이 통과했다.
- localhost 실제 화면 확인은 사용자 환경에서 남아 있다.
