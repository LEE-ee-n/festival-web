# 규칙 대표 이미지 수동 연결

## 목적과 완료 조건

- 페스티벌 기본정보 관리에서 `썸네일 삭제` 오른쪽에 규칙 이미지 불러오기 버튼을 둔다.
- 버튼을 누르면 `normalized_name + 시작일 + 종료일 + .webp` 파일을 Storage 루트에서 정확히 찾는다.
- 파일이 있으면 감사 로그 RPC를 통해 `festivals.thumbnail_url`을 즉시 교체하고 화면 미리보기도 갱신한다.
- 파일이 없거나 규칙값이 잘못되면 예상 파일명을 포함한 오류를 보여준다.

## 범위

- 포함: 개별 페스티벌 기본정보 탭의 버튼·로딩 상태·연결 처리
- 포함: 페스티벌 목록 진입 시 실행되던 자동 연결 제거
- 제외: 기존 이미지 파일 자동 삭제, Storage 업로드, 파일명 자동 변경

## 예상 수정 파일

- `app/admin/festivals/[id]/lineup/components/BasicInfoTab.tsx`
- `app/admin/festivals/[id]/lineup/hooks/useFestivalBasicInfo.ts`
- `app/admin/festivals/page.tsx`
- `PROJECT_STATUS.md`

## 작업 순서

1. [완료] 현재 축제 값으로 예상 파일명을 만든다.
2. [완료] Storage 루트에서 동일한 파일명이 실제로 있는지 확인한다.
3. [완료] 감사 로그 RPC로 대표 이미지 URL을 교체한다.
4. [완료] 버튼 상태와 성공·실패 안내를 추가한다.
5. [완료] 목록 페이지의 1회 자동 연결 로직을 제거한다.

## 위험과 검증

- 같은 이름의 파일만 정확히 연결하고 유사 파일은 연결하지 않는다.
- 이전 Storage 파일은 다른 데이터가 사용할 수 있으므로 자동 삭제하지 않는다.
- 썸네일 규칙 단위 테스트, ESLint, TypeScript 검사를 실행한다.

## 후속 개선

- 같은 파일명으로 이미지를 덮어쓸 때 CDN 캐시 무효화가 필요하면 파일 버전 규칙을 별도로 정한다.

## 결과

- `썸네일 삭제` 오른쪽에서 규칙 이미지를 필요할 때마다 다시 조회할 수 있다.
- 정확한 파일이 있으면 DB와 화면에 즉시 반영되고 감사 로그에도 기록된다.
- ESLint, TypeScript 검사와 썸네일 규칙 단위 테스트를 통과했다.
