# [구현 완료·배포 화면 확인 대기] 2026-08-11 분석 도구 동의 관리

## 목적과 완료 조건

GA4·Microsoft Clarity를 사용자가 분석 처리를 허용한 경우에만 로드하고, 필수 기능은 분석 동의와 무관하게 정상 제공한다.

- 첫 공개 방문에서 `필수만 사용`과 `분석 허용`을 선택할 수 있다.
- 선택 전과 `필수만 사용` 상태에서는 GA4·Clarity 스크립트를 로드하지 않는다.
- 선택은 브라우저에 저장해 매번 묻지 않고 푸터에서 다시 변경할 수 있다.
- 관리자 경로에는 배너와 분석 스크립트를 표시하지 않는다.

## 확정 범위와 제외 범위

- 흰 바탕, 회색 선·글자 중심의 하단 동의 UI
- 브라우저 `localStorage`에 `essential` 또는 `analytics` 선택 저장
- 분석 허용 시에만 기존 `AnalyticsScripts` 렌더링
- 푸터 `분석 설정` 버튼과 개인정보처리방침 안내 갱신
- 제외: 광고 쿠키, 맞춤 광고, 서버 DB에 동의 이력 저장, 로그인 필수 동의화

## 예상 수정 파일과 데이터 흐름

- `lib/analytics/consent.ts`: 저장 키·값 검증·이벤트 이름
- `components/analytics/AnalyticsConsentManager.tsx`: 선택 상태·배너·스크립트 제어
- `components/analytics/AnalyticsScripts.tsx`: 동의 뒤 실행되는 기존 스크립트 유지
- `components/PublicFooter.tsx`: 설정 다시 열기
- `app/layout.tsx`, `app/privacy/page.tsx`, 관련 테스트와 SaaS 계획서

방문 → 저장된 선택 확인 → 선택 없음이면 배너 → `필수만 사용`은 분석 미실행 / `분석 허용`은 GA4·Clarity 실행 → 푸터에서 재선택.

## 작업 순서

1. 순수 동의 값 검증 로직과 테스트를 작성한다.
2. 관리자 제외·초기 미실행·선택 저장·재설정 UI를 구현한다.
3. 분석 스크립트를 동의 관리자 뒤에 연결한다.
4. 개인정보처리방침과 SaaS 계획을 실제 동작에 맞춘다.
5. 전체 테스트, TypeScript, ESLint, 프로덕션 빌드를 검증한다.

## 회귀 위험과 검증 방법

- 선택 전 스크립트가 먼저 실행될 위험: 레이아웃에서 기존 직접 렌더링을 제거하고 동의 상태가 `analytics`일 때만 마운트한다.
- `localStorage` 오류 위험: 읽기·쓰기를 예외 처리하고 선택 없음으로 안전하게 되돌린다.
- 거부 후 기존 분석 실행이 남는 위험: 분석 허용에서 필수만 사용으로 변경하면 저장 후 페이지를 새로고침한다.
- 관리자 분석 위험: 관리자 경로는 배너와 스크립트를 모두 반환하지 않는다.

## 후속 개선점

- 분석 종류가 늘어날 때 목적별 세부 선택
- 필요 시 서버 동의 증빙과 정책 버전 관리

## 실제 구현 및 검증 결과

- 선택값 검증과 관리자 제외를 공통 로직으로 만들고 `localStorage` 키 버전을 고정했다.
- 선택 전과 `필수만 사용` 상태에는 GA4·Clarity를 렌더링하지 않고 `분석 허용` 상태에서만 기존 스크립트를 마운트한다.
- 푸터 `분석 설정`으로 다시 열 수 있고 분석 허용을 철회하면 새로고침해 이미 로드된 스크립트를 제거한다.
- 저장소 접근이 차단된 브라우저에서도 현재 탭의 선택은 적용한다.
- 흰 배경·회색 선의 하단 UI와 개인정보처리방침 안내를 추가했다.
- 관련 테스트 6개, 전체 테스트 305개, TypeScript와 ESLint 오류 0개가 통과했다. 기존 Next.js 탐색 경고 9개는 이번 범위 밖이다.
- 프로덕션 빌드는 컴파일과 TypeScript까지 통과했다. 정적 생성은 Codex 격리 환경의 `.env.local` 접근 차단으로 중단되어 사용자 환경과 배포 화면 확인이 남았다.
