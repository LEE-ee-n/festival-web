# 공개 페이지 SEO 메타데이터·구조화 데이터

## 목적과 완료 조건

- 축제·아티스트 상세 URL마다 실제 데이터에 맞는 제목과 설명을 제공한다.
- 홈페이지에 `WebSite`, 축제 상세에 `Event` JSON-LD를 제공한다.
- 화면에 공개되는 데이터만 검색엔진 구조화 데이터에 포함한다.
- 배포 후 로그아웃 상태의 PC·모바일 공개 화면을 확인한다.

## 확정 범위

- 홈페이지 기본 메타데이터와 `WebSite` 구조화 데이터
- `/festival/[id]`의 동적 제목·설명과 `Event` 구조화 데이터
- `/artist/[id]`의 동적 제목·설명
- 공개 페스티벌만 메타데이터와 구조화 데이터로 조회

## 제외 범위

- DB·RLS 변경
- 대표 이미지 등록 작업
- 검색엔진 순위 보장 및 검색 콘솔 설정 변경
- 관리자 페이지 SEO

## 예상 수정 파일·데이터 흐름

- 공개 상세 페이지의 서버 레이아웃 또는 서버 래퍼에서 Supabase 공개 데이터를 조회한다.
- 메타데이터와 JSON-LD 생성 로직은 공통 유틸리티로 분리한다.
- 기존 클라이언트 상세 화면의 데이터 편집·표시 동작은 변경하지 않는다.

## 작업 순서

1. 현재 공개 페이지와 Supabase 서버 조회 구조를 확인한다.
2. 축제·아티스트별 동적 메타데이터를 구현한다.
3. 홈페이지 `WebSite`, 축제 `Event` JSON-LD를 구현한다.
4. 관련 테스트, 린트, 타입 검사와 빌드를 실행한다.
5. 로그아웃 상태의 PC·모바일 공개 화면을 확인한다.

## 회귀 위험과 검증

- 비공개 축제 정보가 메타데이터로 노출되지 않는지 확인한다.
- 잘못된 ID에서도 빌드·렌더링 오류가 나지 않는지 확인한다.
- JSON-LD가 유효한 JSON이며 화면 데이터와 일치하는지 확인한다.
- 기존 공개 상세 화면과 링크가 정상 동작하는지 확인한다.

## 후속 개선점

- 대표 이미지 준비 후 Open Graph 이미지 연결
- 축제·아티스트 상세 `BreadcrumbList`

## 현재 결과

- 홈페이지 제목·설명과 `WebSite` JSON-LD를 추가했다.
- 공개 축제 상세에 동적 제목·설명과 `Event` JSON-LD를 추가했다.
- 공개 축제 출연 이력이 있는 아티스트 상세에 동적 제목·설명을 추가했다.
- 공개 데이터가 없는 상세 URL은 검색 제외 처리했다.
- 사이트맵의 아티스트도 공개 축제 출연자만 포함하도록 제한했다.
- 전체 테스트 150개, 린트, 타입 검사가 통과했다.
- 사용자 환경에서 프로덕션 빌드가 통과했다.
- 자동 브라우저는 로컬 주소 접근 정책으로 차단되어 로그아웃 PC·모바일 화면 확인이 남아 있다.
