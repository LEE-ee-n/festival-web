# [구현 완료·화면 확인 대기] 아티스트 행 내부 프로필 통합 관리

## 목적과 완료 조건

- `/admin/artists`에서 선택한 아티스트의 기본정보와 프로필 링크를 같은 편집 영역에서 관리한다.
- 전체 표는 가로로 늘리지 않고 로고·Instagram·추천 플레이리스트의 등록 여부만 간단히 표시한다.
- PC 표와 모바일 카드에서 동일하게 선택한 항목 바로 안에서 편집할 수 있으면 완료다.

## 확정 범위

- 목록에 `프로필` 상태 영역 추가
  - 로고 등록 여부
  - Instagram 등록 여부
  - 추천 플레이리스트 등록 여부
  - YouTube 검색은 자동 생성이므로 별도 저장 상태로 취급하지 않음
- `수정` 선택 시 기존 이름·`normalized_name`·별칭 입력과 함께 다음 항목 표시
  - 현재 로고 미리보기
  - Instagram URL
  - 추천 플레이리스트 URL
- 저장·취소 상태와 기존 단일 아티스트 편집 흐름 재사용
- 현재 전체 표 아래에 따로 표시되는 프로필 입력 영역 제거
- `ARTIST_MANAGEMENT.md`와 `PROJECT_STATUS.md` 갱신

## 제외 범위

- 로고 파일 업로드·교체
- YouTube 검색 URL 직접 입력
- Instagram API 연동
- 여러 아티스트 일괄 수정
- DB 구조 및 RPC 변경

## 예상 수정 파일과 데이터 흐름

- `app/admin/artists/page.tsx`
  - 프로필 입력 상태를 행 편집 컴포넌트에 전달하고 표 아래 별도 영역 제거
- `app/admin/artists/components/ArtistManagementTable.tsx`
  - 프로필 등록 상태 표시와 행 내부 편집 컴포넌트 연결
- `app/admin/artists/components/ArtistEditFields.tsx`
  - 기본정보와 프로필 링크를 한 편집 영역으로 구성
- `components/admin/ArtistProfileFields.tsx`
  - 행 내부에서 재사용할 수 있도록 입력 전용 구성으로 조정하거나 기존 편집 컴포넌트에 통합
- `ARTIST_MANAGEMENT.md`, `PROJECT_STATUS.md`
  - 실제 관리 흐름과 검증 상태 기록

데이터 흐름은 `목록 조회 → 선택 행 상태 로드 → 행 내부 입력 → 기존 update_artist_admin RPC 저장 → 목록 재조회`를 유지한다.

## 작업 순서

1. [x] 프로필 등록 여부를 표시하는 작은 상태 컴포넌트를 만든다.
2. [x] 프로필 입력을 기존 행 편집 영역 안으로 이동한다.
3. [x] PC 표 열 너비와 모바일 카드 배치를 조정한다.
4. [x] 표 아래의 중복 프로필 입력 영역을 제거한다.
5. [x] 관련 문서를 갱신하고 테스트·타입 검사·린트를 실행한다.
6. [ ] localhost에서 PC·모바일 실제 화면과 저장 동작을 확인한다.

## 회귀 위험과 검증

- 편집 행의 `colSpan` 불일치로 표가 깨질 수 있으므로 PC 실제 화면을 확인한다.
- 모바일 입력 폭과 버튼 줄바꿈을 확인한다.
- 기존 이름·별칭 저장과 프로필 링크 저장이 함께 정상 반영되는지 확인한다.
- 취소 후 다른 아티스트를 선택했을 때 이전 링크가 남지 않는지 확인한다.
- 관련 테스트, 전체 타입 검사, 변경 파일 ESLint를 실행한다.

## 후속 개선점

- 로고 파일 업로드와 자동 파일명·Storage 연결
- 프로필 누락 아티스트 필터
- 대량 등록용 CSV 또는 관리자 큐

## 실제 결과

- PC 목록에 프로필 상태 열을 추가하고 선택 행을 6열 전체 너비 편집 패널로 전환했다.
- 모바일은 선택 카드 안에서 같은 기본정보·프로필 입력 컴포넌트를 사용한다.
- YouTube는 자동 검색 링크, Instagram과 추천 플레이리스트는 저장 가능한 입력값으로 유지했다.
- 전체 테스트 197개, 타입 검사, 변경 파일 ESLint와 `git diff --check`가 통과했다.
- 이 실행 환경의 브라우저 보안 정책이 localhost 접속을 차단해 실제 화면 검증은 사용자의 확인이 필요하다.
