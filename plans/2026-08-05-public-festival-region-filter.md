# [구현 완료·화면 확인 대기] 공개 페스티벌 지역 필터

## 문서 식별

- 작업 문서: `plans/2026-08-05-public-festival-region-filter.md`
- 작업 대상 화면: `http://localhost:3000/festivals`, `http://localhost:3000/`
- 기존 기준 문서: `plans/2026-07-30-public-festival-overview.md`
- DB migration 번호: 없음
- 행정구역 기준 확인:
  - 행정안전부 주민등록 인구통계: `https://jumin.mois.go.kr/etcStatAvgAge.do`
  - 국가데이터처 17개 시·도 축약 구분 자료: `https://sri.kostat.go.kr/boardDownload.es?bid=11843&list_no=416274&seq=1`

## 목적과 완료 조건

- `/festivals`에서 사용자가 `지역 필터`를 눌러 원하는 지역 하나를 선택할 수 있다.
- 필터 기준은 `festivals.region` 값만 사용하고 17개 시·도 축약명으로 분류한다.
- `location`(장소)과 `address`(상세 주소)는 지역 판정이나 보정에 사용하지 않는다.
- 기존 `전체 / 예정 / 진행중 / 종료` 상태 필터와 지역 필터가 동시에 적용된다.
- PC와 모바일에서 필터 선택, 해제, 목록 표시가 깨지지 않는다.
- 같은 지역 필터를 메인 달력에서도 사용하고 달력 막대와 날짜별 목록을 함께 제한한다.

## 확정 동작

### 지역 표준 분류

- 화면의 표준 지역값은 아래 17개 축약명으로 고정한다.
  - `서울`, `경기`, `인천`
  - `강원`
  - `대전`, `세종`, `충북`, `충남`
  - `광주`, `전북`, `전남`
  - `대구`, `경북`
  - `부산`, `울산`, `경남`
  - `제주`
- `region`의 앞뒤 공백을 제거한 뒤 아래 정식·이전 명칭을 표준 축약명으로 매핑한다.
  - `서울특별시` → `서울`
  - `부산광역시` → `부산`
  - `대구광역시` → `대구`
  - `인천광역시` → `인천`
  - `광주광역시` → `광주`
  - `대전광역시` → `대전`
  - `울산광역시` → `울산`
  - `세종특별자치시` → `세종`
  - `경기도` → `경기`
  - `강원도`, `강원특별자치도` → `강원`
  - `충청북도` → `충북`
  - `충청남도` → `충남`
  - `전라북도`, `전북특별자치도` → `전북`
  - `전라남도` → `전남`
  - `경상북도` → `경북`
  - `경상남도` → `경남`
  - `제주도`, `제주특별자치도` → `제주`
- 이미 축약명으로 저장된 값은 그대로 인정한다.
- `null`, 빈 문자열, 공백뿐인 값은 지역 선택지에서 제외하지만 `전체 지역` 목록에서는 축제를 유지한다.
- 17개 표준값에 해당하지 않는 비어 있지 않은 값도 `전체 지역`에서는 유지하고 개발 콘솔 오류를 만들지 않는다. 이번 작업에서 `기타` 선택지는 만들지 않는다.
- 주소나 장소를 이용해 알 수 없는 `region` 값을 추정하지 않는다.
- 선택지는 17개 표준 순서 중 현재 공개 축제에 실제로 존재하는 지역만 표시한다.
- `전체 지역`을 선택하면 지역 조건을 해제한다.
- 한 번에 하나의 지역만 선택한다. 다중 선택은 구현하지 않는다.

### 재사용 가능한 필터 컴포넌트

- 지역 전용 드롭다운으로 만들지 않고 공개 페스티벌 목록에서 재사용할 수 있는 범용 단일선택 필터 컴포넌트로 분리한다.
- 권장 파일은 `components/festivals/filters/FestivalFilterMenu.tsx`다.
- 컴포넌트는 `region`, Supabase, 날짜 상태를 알지 않는다.
- 컴포넌트가 받는 책임은 다음으로 제한한다.
  - 필터 제목
  - 현재 선택값
  - 전체 해제 항목 문구
  - `{ value, label }[]` 선택지
  - 변경 콜백
  - 선택적으로 버튼의 표시 문구를 만드는 값
- 열기·닫기, 바깥 클릭, `Escape`, 접근성 속성, 모바일 패널 폭은 공통 컴포넌트가 담당한다.
- 지역 매핑·고유 목록·교차 필터링은 `lib/festivals/publicFestivalOverview.ts`가 담당한다.
- 이후 가격, 장르 등 다른 단일선택 필터를 추가할 때 같은 컴포넌트에 선택지만 전달할 수 있어야 한다.
- 아직 요구되지 않은 다중선택·전체 필터 상태 관리 프레임워크는 만들지 않는다.
- 필터 트리거는 설치된 `lucide-react`의 일반적인 깔때기 모양 `Funnel` SVG 아이콘을 사용한다.
- `전체 지역`은 초기화 명령이 아니라 `지역 조건 없이 전체를 표시`하는 정상 선택값이다.
- 공통 컴포넌트에서 `reset`, `null`, `__reset__` 같은 초기화 개념을 제거하고 `전체 지역`도 다른 항목과 동일한 일반 option으로 전달한다.
- 지역 연결은 `FestivalRegionFilter` 래퍼로 분리해 `/festivals`와 메인 달력이 같은 UI를 사용한다.

### 메인 달력 배치와 동작

- PC 오른쪽 도구 순서는 `검색 → 지역 필터 → 전체 페스티벌 보기 → 오늘로 이동`이다.
- 모바일은 왼쪽에 `검색 → 지역 필터`, 오른쪽에 `전체 페스티벌 보기 → 오늘로 이동`을 2개씩 배치한다.
- 지역 필터는 현재 조회된 달의 공개 축제 `region`으로 선택지를 만든다.
- 선택한 지역은 달력의 축제 막대, lane 계산, 선택 날짜의 축제 목록에 모두 적용한다.
- 지역을 바꾸면 현재 선택된 개별 축제는 해제하고, 열려 있는 날짜 패널은 해당 지역의 목록 상태로 돌아간다.
- 통합 검색에서 축제를 직접 선택하면 검색 결과가 지역 필터로 숨지 않도록 지역 선택값을 `전체 지역`으로 변경한다.
- 최근 등록 알림 문구는 이번 지역 필터 대상에 포함하지 않는다.

### 상태 필터와 결합

- 필터 순서는 결과상 동일해야 하지만 구현 흐름은 `선택 지역 적용 → 선택 상태 적용 → 기존 정렬`로 통일한다.
- 지역이 선택되면 기존 상태 버튼의 개수는 해당 지역 안에서의 `전체 / 예정 / 진행중 / 종료` 개수로 다시 계산한다.
- 지역 선택지는 승인된 전체 공개 목록에서 만들며 현재 상태 필터에 따라 사라지지 않는다.
- 결과가 없을 때 문구는 특정 상태만 언급하지 않도록 `선택한 조건의 페스티벌이 없습니다.`로 표시한다.

### UI와 접근성

- 기존 상태 필터 바로 아래 또는 같은 필터 영역에 `지역 필터` 트리거 버튼을 둔다.
- 미선택 상태의 버튼 문구는 `지역 필터`, 선택 후에는 `지역: {선택값}`으로 표시한다.
- 버튼을 누르면 `전체 지역`과 실제 지역 선택지가 보이는 패널을 연다.
- 선택한 항목은 테두리 또는 체크 표시로 명확히 구분하되 기존 `festival-night`, `surface`, `line` 색상 토큰과 `lib/typography.ts`를 재사용한다.
- 항목을 선택하면 패널을 닫는다.
- 바깥 클릭과 `Escape`로도 패널을 닫는다.
- 트리거에 `aria-expanded`, 선택 항목에 `aria-pressed` 또는 동등한 접근성 상태를 제공한다.
- 모바일에서 패널이 화면 너비를 넘지 않고, 긴 지역명도 잘리지 않게 한다.
- 모바일 패널은 viewport 좌우 여백을 고정한 하단 패널로 표시하고, `sm` 이상에서는 사용 위치에 따라 트리거의 왼쪽 또는 오른쪽에 맞춘 드롭다운으로 표시한다.

## 권장 순수 함수

이름은 기존 코드와 충돌하면 조정해도 되지만 책임은 유지한다.

- `normalizePublicFestivalRegion(region: string | null): PublicFestivalRegion | null`
- `getPublicFestivalRegions(festivals): string[]`
- `filterPublicFestivalsByRegion(festivals, activeRegion)`

`PublicFestivalRegion`은 위 17개 축약명만 허용하는 문자열 유니언 타입으로 정의한다.
선택 상태는 `type PublicFestivalRegionFilter = "all" | PublicFestivalRegion`처럼 전체 지역도 명시적인 값으로 표현한다.

## 필수 테스트 사례

- `서울`, `서울특별시`, 중복된 `서울`은 선택지 하나의 `서울`로 합쳐진다.
- `강원도`와 `강원특별자치도`는 `강원`으로 합쳐진다.
- `전라북도`와 `전북특별자치도`는 `전북`으로 합쳐진다.
- `제주도`와 `제주특별자치도`는 `제주`로 합쳐진다.
- 17개 정식명·축약명이 모두 올바른 축약명으로 변환된다.
- `null`, `""`, `"   "`는 지역 선택지에서 제외된다.
- 알 수 없는 지역값과 지역 미정 축제는 `전체 지역`에서는 사라지지 않는다.
- `서울` 선택 시 `region`을 정리한 값이 정확히 `서울`인 축제만 남는다.
- `전체 지역` 상태에서는 기존 전체 목록이 유지된다.
- `서울 + 예정`, `서울 + 진행중`, `부산 + 종료`처럼 지역과 날짜 상태가 교차 적용된다.
- 선택 지역 기준으로 상태별 개수가 다시 계산된다.
- 기존 상태 판정과 정렬 테스트가 모두 계속 통과한다.

## 회귀 위험과 검토 기준

- `location`이나 `address`를 잘못 지역값으로 사용하는지 확인한다.
- 필터링 때문에 기존 승인·공개 상태 조회 조건이 바뀌지 않았는지 확인한다.
- 지역 필터 후 상태 개수와 실제 카드 수가 모순되지 않는지 확인한다.
- 지역을 바꾼 뒤 기존 상태 선택이 유지되는지 확인한다.
- 필터 패널 바깥 클릭이 카드 링크 클릭이나 다른 버튼 입력을 막지 않는지 확인한다.
- 이벤트 리스너를 추가했다면 컴포넌트 해제 시 정리되는지 확인한다.
- 지역 값이 없는 축제는 `전체 지역`에서는 보이되 특정 지역에서는 제외되는지 확인한다.
- 로딩·오류·빈 결과 UI가 기존보다 악화되지 않았는지 확인한다.
- 불필요한 DB migration, 새 라이브러리, `any`, 중복 필터 로직이 없는지 확인한다.
- 공통 필터 컴포넌트에 지역 매핑·Supabase 조회·날짜 상태 로직이 섞이지 않았는지 확인한다.
- 공통 필터 컴포넌트를 다른 단일선택 옵션에도 재사용할 수 있는 props 구조인지 확인한다.
- `reset`, `null`, `__reset__` 같은 초기화 상태 없이 `전체 지역`이 일반 option으로 동작하는지 확인한다.
- 메인 달력에서 필터 후 막대, lane, 날짜별 목록이 같은 축제 집합을 사용하는지 확인한다.
- 모바일 왼쪽 두 버튼과 오른쪽 두 버튼이 320px 수준에서도 중앙 월 제목을 침범하지 않는지 확인한다.

## Qwen 완료 보고 형식

Qwen은 구현을 끝낸 뒤 아래 순서로 한 번에 보고한다.

1. 구현 결과 요약
2. 실제 수정·추가한 파일 목록과 각 파일의 책임
3. 지역·상태 필터 데이터 흐름
4. 테스트·TypeScript·ESLint 각각의 실제 명령과 결과
5. localhost PC·모바일 확인 결과 또는 확인하지 못한 정확한 이유
6. 남은 문제와 회귀 위험
7. Codex가 검토해야 할 핵심 코드 위치와 판단이 필요한 사항

도구 성공만으로 실제 화면 확인을 완료 처리하지 않는다. 확인하지 못한 항목은 `미검증`으로 명시한다.

## Codex 후속 검토 항목

- 계획에 없는 DB·관리자·홈 달력 변경이 섞이지 않았는지 diff를 확인한다.
- 순수 함수의 공백 처리, 정확 일치, 고유 목록, 한글 정렬 테스트를 확인한다.
- 강원·전북·제주의 이전 명칭과 특별자치도 명칭이 같은 축약값으로 매핑되는지 확인한다.
- `region` 외의 `location`, `address`를 판정에 사용하지 않았는지 확인한다.
- 상태 개수가 선택 지역 기준이고 카드 결과와 일치하는지 확인한다.
- 드롭다운의 바깥 클릭·Escape·접근성 속성과 모바일 폭을 확인한다.
- 공통 필터 컴포넌트가 지역 도메인 로직을 모르고 다른 단일선택 필터에 재사용 가능한지 확인한다.
- 전체 테스트, 타입 검사, 변경 파일 ESLint를 Codex가 다시 실행한다.
- 가능하면 localhost에서 전체 지역 → 서울 → 다른 상태 → 전체 지역 순으로 직접 확인한다.

## 후속 개선점

- 지역 값 표준화가 필요하면 실제 데이터 현황을 먼저 조사한 뒤 별도 계획으로 진행한다.
- URL query 공유는 이번 기능 검증 후 별도 판단한다.

## 실제 결과

- `/festivals`와 메인 달력이 같은 `FestivalRegionFilter`를 재사용한다.
- 필터 버튼은 `lucide-react`의 `Funnel` SVG 아이콘으로 통일했다.
- `전체 지역`은 초기화가 아닌 명시적인 `"all"` 일반 선택값으로 처리한다.
- 모바일 필터 패널은 viewport 좌우 여백을 보장하는 하단 고정형, PC는 사용 위치에 맞춘 좌·우 정렬 드롭다운으로 구현했다.
- 메인 PC는 `검색 → 필터 → 전체 페스티벌 보기 → 오늘`, 모바일은 왼쪽 `검색·필터`, 오른쪽 `전체보기·오늘` 순서로 배치했다.
- 메인 달력의 막대, lane, 선택 날짜 목록이 같은 지역 필터 결과를 사용한다.
- 통합 검색에서 축제를 직접 선택하면 지역값을 `전체 지역`으로 변경한다.
- 전체 테스트 217개, TypeScript 검사, 관련 파일 ESLint와 `git diff --check`가 통과했다.
- 새 아이콘 배치와 필터 패널의 PC·모바일 실제 화면 확인은 남아 있다.
- Qwen localhost PC 확인(2026-08-05): `/festivals`에서 지역 필터 열기, `서울` 선택 시 트리거 문구·상태 개수(16/10/0/6)·목록 변경, `서울+종료` 교차 필터 6건, `전체 지역` 해제 후 전체 개수(72/54/1/17) 복원을 확인했다. 모바일 폭과 메인 달력 화면은 미검증.
