# [구현 완료·배포 검증 대기] 티켓 URL 오전 이메일 알림

## 목적과 완료 조건

- 매일 오전 9시(KST)에 유료·무료유료혼합 축제의 티켓을 점검한다.
- `open_at`이 실행 시각 이후이고 `ticket_url`이 비어 있는 티켓만 한 통의 이메일로 알린다.
- 대상이 없으면 이메일을 보내지 않는다.
- 수신 메일에는 축제명, 회차명, 오픈 시각, 판매처와 관리자 관리 링크를 표시한다.

## 확정 범위

- 무료(`free`) 축제는 제외한다.
- 유료(`paid`)와 무료·유료 혼합(`partial_free`)만 포함한다.
- 이미 오픈 시간이 지났거나 티켓 URL이 있으면 제외한다.
- Vercel Production Cron을 UTC 00:00(한국 시간 오전 9시)로 설정한다.
- Resend API로 `TICKET_ALERT_RECIPIENT_EMAIL` 한 명에게 발송한다.
- Cron 요청은 `CRON_SECRET`으로 검증한다.

## 제외 범위

- 티켓이 아예 없거나 오픈일이 미정인 축제의 자동 탐색·알림
- Discord 알림, 사용자별 구독, 푸시 알림
- 티켓 URL 자동 수집·자동 저장
- DB 스키마 변경

## 예상 수정 파일·흐름

- `app/api/cron/ticket-url-alert/route.ts`: 서버에서 Supabase 공개 조회, 조건 판별, Resend 이메일 발송.
- `lib/festivals/ticketUrlAlert.ts`: 조건 판별과 메일 표시 데이터 정규화 공통 함수.
- `vercel.json`: Production Cron 일정 등록.
- `tests/ticketUrlAlert.test.ts`: 무료 제외, URL 존재 제외, 과거 오픈 제외, 미래 오픈 포함 검증.
- `PROJECT_STATUS.md`: 구현·운영 확인 상태 기록.

흐름: Vercel Cron → 비밀값 검증 → 티켓·축제 조회 → 대상 0건이면 종료 → 대상 목록 이메일 1통 발송.

## 작업 순서

1. 기존 공개 Supabase 조회 권한으로 필요한 필드가 조회되는지 확인한다.
2. 티켓 URL 알림 대상 순수 판별 함수를 만들고 테스트한다.
3. 보호된 Cron API와 Resend 발송을 구현한다.
4. 오전 9시(KST) Production Cron을 등록한다.
5. 타입 검사·관련 테스트·린트를 실행한다.
6. 배포 후 실제 대상 건으로 수신을 확인하고, URL 입력 후 다음 실행에서 제외되는지 확인한다.

## 회귀 위험과 검증

- Cron 외부 호출을 `CRON_SECRET` 검증으로 차단한다.
- 이메일 발송 실패는 5xx로 남겨 Vercel 알림·로그에서 확인한다.
- 같은 날 여러 티켓이 있어도 한 통으로 묶어 과다 발송하지 않는다.
- 무료 축제와 URL 입력 완료 티켓은 테스트로 제외를 고정한다.
- Vercel Hobby Cron은 하루 1회이며 정확한 분 단위 실행 보장은 아니므로 오전 점검 알림으로만 사용한다.

## 후속 개선점

- 필요 시 이메일 발송 이력과 재알림 간격을 DB에 저장한다.
- 관리자 데이터 점검판에 같은 조건의 `티켓 URL 확인 필요` 항목을 추가한다.
