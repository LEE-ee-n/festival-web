# [완료] 2026-08-11 관리자 헤더 진입 버튼·TOTP 분리

## 목적과 완료 조건

관리자 역할 계정은 TOTP 인증 전에도 헤더에서 관리자 진입 버튼을 볼 수 있게 한다. 버튼을 누르면 관리자 로그인 화면으로 이동하며, 실제 관리자 기능은 기존처럼 TOTP `aal2` 인증 뒤에만 사용할 수 있어야 한다.

## 확정 범위와 제외 범위

- 관리자 역할 여부와 현재 관리자 기능 이용 가능 상태를 헤더에서 구분한다.
- 관리자 역할 계정에는 MFA 상태와 관계없이 `관리자` 버튼을 표시한다.
- TOTP 미인증 상태에서 `/admin` 진입 시 기존 `/admin/login` 이동과 TOTP 요구를 유지한다.
- 일반 회원에게는 관리자 버튼을 표시하지 않는다.
- 관리자 RPC, RLS, DB 권한과 TOTP 정책은 변경하지 않는다.

## 예상 수정 파일·데이터 흐름

- `components/CommonHeader.tsx`
- 필요 시 헤더 상태 판정 관련 테스트
- `PROJECT_STATUS.md`

로그인 사용자 조회 → `hasAdminRole`이면 헤더 버튼 표시 → `/admin` 진입 → `aal2`가 아니면 `/admin/login` → TOTP 완료 후 관리자 기능 허용.

## 작업 순서

1. [완료] 헤더가 관리자 진입 표시에는 `hasAdminRole`을 사용하게 변경한다.
2. [완료] 관리자 역할 계정이면 TOTP 전에도 관리자 버튼과 관리자 계정 표시를 노출한다.
3. [완료] 기존 관리자 레이아웃과 `is_admin()`의 `aal2` 강제 구현을 유지하고 관련 테스트를 통과했다.
4. [완료] 일반 회원과 비로그인 상태의 기존 헤더 분기를 유지했다.
5. [부분 완료] 테스트·타입 검사·관련 린트와 비로그인 localhost 화면을 확인했다. 관리자 로그인 화면은 배포 후 운영 세션에서 확인한다.

## 회귀 위험과 검증 방법

- 일반 회원 노출 위험: 일반 회원에서 `hasAdminRole=false`와 버튼 미표시를 확인한다.
- 권한 우회 위험: 관리자 `aal1`에서 `/admin` 기능이 열리지 않고 `/admin/login`으로 이동하는지 확인한다.
- 인증 후 회귀 위험: 관리자 `aal2`에서 기존 관리자 화면과 버튼이 정상인지 확인한다.

## 후속 개선점

- TOTP 미인증 상태의 버튼 문구를 `관리자 인증`으로 구분할지 검토한다.

## 실제 결과

- `CommonHeader`는 관리자 기능 이용 가능 여부가 아니라 `profiles.role = admin` 판정으로 관리자 계정 문구와 버튼을 표시한다.
- 버튼은 `/admin`으로 연결되고 기존 관리자 레이아웃이 `aal1` 관리자만 `/admin/login`으로 보내므로 TOTP 전에는 관리자 기능을 사용할 수 없다.
- 관리자 RPC와 DB의 `aal2` 강제 정책은 수정하지 않았다.
- 전체 테스트 297개와 TypeScript 검사가 통과했고 관련 ESLint 오류는 0개다. 기존 로그아웃 내부 이동 방식 경고 1개는 이번 범위 밖으로 유지했다.
- 프로덕션 빌드는 컴파일과 TypeScript까지 통과했으나 격리 환경의 `.env.local` 읽기 제한으로 정적 페이지 생성 단계에서 중단됐다.
- localhost 비로그인 헤더가 기존처럼 로그인 버튼만 표시되는 것을 확인했다. 관리자 역할 화면은 배포 후 운영 계정에서 최종 확인한다.
