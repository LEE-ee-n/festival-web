# [구현 완료·화면 확인 대기] 축제 기간 밖 아티스트 공연일 데이터 점검

## Qwen 작업 지시

이 문서의 확정 범위 안에서만 구현한다. 구현 중 범위·데이터 규칙·DB 변경이 필요해 보이면 임의로 넓히지 말고 중단한 뒤 질문한다. 기존 사용자 변경사항은 되돌리거나 정리하지 않는다.

## 목적과 완료 조건

- 관리자 메인의 기존 `데이터 점검`에 `축제 기간 밖 아티스트 공연일` 항목을 추가한다.
- 예정·진행 중 축제에서, 아티스트의 `festival_artists.performance_date`가 축제 `start_date`~`end_date`의 **양 끝을 포함한 기간 밖**이면 점검 후보로 표시한다.
- 점검판은 문제 축제를 찾아 라인업 관리 화면으로 연결하고, 실제 오류 문구는 그 화면의 아티스트별 공연 날짜 입력칸 바로 아래에 표시한다.
- 이 기능은 날짜를 자동 변경·삭제·추정하지 않는다.

완료 기준은 새 점검 항목의 집계·필터·라인업 관리 이동이 동작하고, 라인업 화면에서 해당 날짜 입력칸마다 오류 문구가 보이며, 순수 로직 테스트와 관련 검사 결과가 보고되는 것이다.

## 확정 범위

- 기존 `components/admin/AdminFestivalDataQuality.tsx`와 `lib/festivals/festivalDataQuality.ts`를 확장한다.
- 기존 축제 조회에 필요한 라인업 데이터를 추가로 읽는다. 각 행에는 최소 `festival_id`, `performance_date`, 아티스트 표시 이름을 포함한다.
- 아래 조건을 모두 만족하는 라인업 행만 오류 후보로 판정한다.
  - 축제가 기존 점검판 대상과 동일하게 `ended`·`cancelled`가 아님
  - `performance_date`가 비어 있지 않음
  - `performance_date < start_date` 또는 `performance_date > end_date`
- 날짜 비교는 `YYYY-MM-DD` 형식의 날짜 문자열끼리 수행한다. 시간대 변환이나 `Date` 객체로 인한 날짜 이동을 만들지 않는다.
- 같은 축제에서 여러 아티스트가 기간 밖이면 점검판의 축제 카드/행은 한 번만 표시하고, 오류 건수만 표시한다. 아티스트명·공연일 오류 문구는 점검판이 아니라 라인업 화면에서만 보인다.
- 새 요약 버튼과 필터를 추가한다. 필터된 행의 버튼은 기존 경로 `/admin/festivals/[id]/lineup`로 이동한다.
- 라인업 관리 화면은 축제의 시작일·종료일을 기존 기본정보 로딩 결과에서 전달받는다. 기존 아티스트 행의 `공연 날짜` 입력칸 바로 아래에 `축제 기간(YYYY-MM-DD ~ YYYY-MM-DD) 밖의 날짜입니다.` 오류 문구를 보인다.
- 새 아티스트 추가 영역의 `공연 날짜` 입력칸에도 같은 오류 문구를 즉시 보인다.
- 오류 문구는 입력값이 기간 안으로 바뀌면 즉시 사라진다. 저장을 막지 않으며, 자동으로 날짜를 고치지 않는다.
- 로딩·조회 실패·해당 없음 상태는 기존 점검판 패턴을 유지한다.
- 단위 테스트에는 기간 시작일/종료일은 정상, 시작 전·종료 후는 오류, 날짜 미정 제외, 종료·취소 축제 제외, 한 축제의 복수 오류 행을 포함한다.

## 제외 범위

- DB migration, RPC, RLS, 테이블·칼럼 추가
- 자동 보정, 일괄 저장, 알림, 삭제
- 축제 기간 자체의 정확성 판정
- `performance_date`가 비어 있는 라인업을 오류로 처리
- 과거 종료·취소 축제의 일괄 정비
- 공개 페이지 표시 규칙 변경
- 기존 누락 항목의 기준 변경

## 예상 수정 파일·데이터 흐름

- `lib/festivals/festivalDataQuality.ts`: 새 이슈 키·표시명, 라인업 입력 타입, 기간 밖 판정, 축제별 오류 상세와 집계를 순수 함수로 추가
- `components/admin/AdminFestivalDataQuality.tsx`: `festivals`와 `festival_artists`를 읽어 순수 함수에 전달하고, 요약/필터/오류 건수/UI를 표시
- `app/admin/festivals/[id]/lineup/page.tsx`, `hooks/useFestivalBasicInfo.ts`, `hooks/useFestivalArtists.ts`: 축제 기간을 라인업 입력 UI에 전달
- `app/admin/festivals/[id]/lineup/components/ArtistLineupTable.tsx`, `components/ArtistAddSection.tsx`: 기간 밖 날짜의 입력칸 바로 아래 오류 문구 표시
- `tests/festivalDataQuality.test.ts`: 기간 비교와 축제별 그룹화 회귀 테스트 추가. 필요하면 날짜 오류 메시지/판정용 순수 함수의 단위 테스트도 추가
- `ARCHITECTURE.md`: 점검판이 라인업 공연일 기간 검사를 포함한다고 짧게 갱신
- `PROJECT_STATUS.md`: 진행 상태·검증 결과·남은 실제 화면 확인을 갱신
- 이 계획 문서: 작업 중 체크박스와 구현 결과를 실제 결과로 갱신

데이터 흐름: 관리자 메인 진입 → 기존 `festivals` 조회 + `festival_artists`의 공연일 조회 → 순수 함수가 축제 기간과 비교·축제별 그룹화 → 요약/필터/오류 건수 표시 → 기존 라인업 관리 화면 진입 → 축제 기간과 각 공연일을 비교 → 해당 날짜 입력칸 아래 오류 문구 표시 → 관리자가 직접 저장.

## 회귀 위험과 검증 방법

- 1일짜리 축제에서 동일 날짜 공연은 오류가 아니어야 한다.
- 다일 축제의 시작·종료일 공연은 정상이고, 그 전날·다음 날만 오류여야 한다.
- 축제 하나의 오류 라인업 여러 건이 목록의 중복 축제 행을 만들면 안 된다.
- 기간 밖 아티스트는 점검판이 아니라 라인업 관리의 해당 `공연 날짜` 입력칸 바로 아래에서 오류 문구를 봐야 한다.
- 기존 행을 기간 안 날짜로 바꾸거나 새 아티스트 추가 날짜를 기간 안으로 고르면 오류 문구가 즉시 사라져야 한다.
- 기존 Instagram·홈페이지·썸네일·장소·가격 누락 집계와 필터가 달라지면 안 된다.
- 관리자 조회 권한 오류가 빈 목록으로 숨겨지면 안 된다.
- 날짜가 null인 라인업은 날짜 미정일 뿐 이번 오류가 아니다.
- 실제 수정은 기존 라인업 저장·감사 기록 흐름을 그대로 사용하며, 점검판에서는 쓰기 요청을 보내지 않는지 확인한다.

## 후속 개선점

- 운영 기준이 정해지면 종료 축제도 별도 필터에서 과거 데이터 정비 대상으로 볼 수 있다.
- 오류 후보를 정기 알림으로 보내는 기능은 오탐 기준이 충분히 검증된 뒤 별도 계획으로 검토한다.
- 축제 기본정보 날짜 변경 직후 라인업 불일치를 강조하는 흐름은 자동 수정 없이 별도 UX 작업으로 검토한다.
