# 기존 축제 최종 반영 충돌·재시도 수정

## 목적과 완료 조건

- 동일한 값을 다시 저장했을 때 `updated_at`만 바뀌지 않게 한다.
- 기존 축제 수정 초안은 실제 축제·라인업·티켓 내용이 바뀐 경우에만 충돌로 차단한다.
- 충돌 오류가 Supabase에서 자동 재시도되지 않게 한다.
- 임시 차단한 `finalize_festival_update_draft` 실행 권한을 복구한다.

## 범위

- 신규 DB 마이그레이션에서 `set_updated_at()`과 `finalize_festival_update_draft()`를 교체한다.
- 관련 DB 문서를 갱신한다.
- 관리자 화면의 단계·선택·임시저장 동작은 변경하지 않는다.

## 작업 순서

1. [완료] 실제 행 내용이 달라질 때만 `updated_at`을 갱신한다.
2. [완료] 최종 반영 충돌 검사를 전체 데이터 해시만 사용하도록 바꾼다.
3. [완료] 재시도용 `40001` 대신 일반 오류 코드 `22023`을 사용한다.
4. [완료] 최종 반영 RPC 실행 권한을 `authenticated`에 다시 부여한다.
5. [완료] 테스트·린트·타입 검사를 실행한다.

## 위험과 검증

- 실제 운영 데이터가 바뀌면 전체 데이터 해시가 달라져 기존처럼 최종 반영을 차단해야 한다.
- 동일 값 재저장은 `updated_at`과 데이터 해시를 모두 유지해야 한다.
- 운영 DB 적용 후 초안 9번이 반복 요청 없이 한 번만 처리되는지 확인한다.

## 검증 결과

- TypeScript 검사 통과 (`--incremental false`).
- 자동 테스트 138개 중 136개 통과. 나머지 2개는 읽기 전용 실행 환경에서 테스트 임시 폴더를 만들 수 없어 실패했다.
- ESLint는 기존 `useFestivalArtists.ts` 오류 1건과 Bot Chrome 프로필 생성 파일 때문에 실패했으며 이번 SQL 변경과 무관하다.
- 운영 DB 적용 및 초안 9번 최종 반영 확인은 사용자 실행이 필요하다.

## 후속 개선

- 실제 데이터 충돌 시 최신 값을 다시 불러와 비교 기준을 갱신하는 전용 기능은 별도 작업으로 추가한다.
