# 공개 축제·아티스트 통합 검색 계획

상태: 구현 완료 · localhost 화면 확인 대기

## 목적과 완료 조건

- 현재 모바일 전용 축제 검색을 모바일과 PC에서 모두 사용할 수 있게 한다.
- 한 검색창에서 공개 축제와 아티스트를 함께 검색한다.
- 검색 결과를 종류별로 구분하고 선택한 대상의 기존 상세 화면으로 이동한다.

## 확정 범위

- 모바일의 기존 검색 버튼과 모달 흐름을 유지한다.
- PC 달력 헤더에도 검색 버튼을 표시한다.
- 별도의 `축제`·`아티스트` 구분 제목 없이 축제 결과를 먼저, 아티스트 결과를 그 아래에 이어서 표시한다.
- 축제 또는 아티스트 결과가 없으면 해당 종류의 빈 구역을 표시하지 않는다.
- 축제 결과는 현재처럼 날짜를 표시하고 아티스트 결과는 날짜 없이 표시해 구분한다.
- 축제는 이름, 검색 별칭, `normalized_name`을 검색한다.
- 아티스트는 표시 이름, `normalized_name`, 별칭, `normalized_alias`를 검색한다.
- 축제 선택은 현재처럼 시작 월로 이동하고 축제 패널을 연다.
- 아티스트 선택은 `/artist/[id]` 상세 페이지로 이동한다.
- 입력 후 300ms 지연 검색, 중복 제거, 로딩·오류·결과 없음 표시를 유지한다.

## 사용자 승인 결과와 남은 확인

- PC 검색 버튼 위치는 달력 헤더 오른쪽의 `오늘` 버튼 왼쪽으로 한다.
- 아티스트는 공개 DB에 등록된 전체 아티스트를 검색 대상으로 한다.
  - 출연 축제가 없는 아티스트도 결과에 나올 수 있다.
  - 대안은 승인된 공개 축제에 연결된 아티스트만 검색하는 것이다.
- 유사도 추측 검색은 넣지 않고 부분 일치와 정규화 일치만 사용한다.
- 결과 종류를 나타내는 별도 구분 제목은 우선 넣지 않는다.
- 아티스트 이름 아래에 별칭을 작게 표시하고, 별칭이 없으면 `normalized_name`을 표시한다.
- 축제와 아티스트 결과는 각각 최대 10개 표시한다.
- `%`, `_`, `\`은 부분 검색 와일드카드가 아니라 일반 입력 문자로 처리한다.

## 작업 순서

1. 공개 검색 결과 타입과 정규화·중복 제거 공통 함수를 만든다.
2. 축제와 아티스트 쿼리를 병렬 실행한다.
3. 검색 모달을 PC에서도 표시하고 축제 다음에 아티스트 결과를 이어서 표시한다.
4. 축제 선택과 아티스트 선택 동작을 각각 연결한다.
5. 모바일·PC 반응형 디자인을 점검한다.
6. 테스트, 타입 검사, 변경 파일 린트를 실행한다.

## 유지할 규칙

- 축제는 `approved`이며 `cancelled`가 아닌 데이터만 표시한다.
- 아티스트 별칭의 띄어쓰기 차이는 `normalized_alias` 검색으로 보완한다.
- 관리자용 수정·유사도 검색 기능은 공개 검색에 연결하지 않는다.
- 검색만 추가하며 달력 월 이동·스와이프·휠 동작은 변경하지 않는다.
- `.env` 파일은 읽거나 수정하지 않는다.

## 회귀 위험

- 아티스트 별칭 관계 조회 결과가 배열 또는 단일 객체로 반환될 수 있다.
- 빠르게 입력할 때 이전 요청 결과가 늦게 도착할 수 있으므로 취소 상태를 유지해야 한다.
- PC 헤더의 검색·오늘 버튼 폭 때문에 작은 태블릿 구간에서 월 제목이 밀릴 수 있다.
- 아티스트 전체 공개 검색은 아직 공개 축제에 연결되지 않은 아티스트도 노출할 수 있다.
- `ALI`처럼 표시 이름이 같은 서로 다른 아티스트는 이름만으로 구분하기 어렵다.

## 검증 항목

- 모바일과 PC에서 검색 버튼과 모달이 정상 표시된다.
- 축제 이름·별칭·`normalized_name`으로 검색된다.
- 아티스트 이름·별칭·띄어쓰기 없는 별칭·`normalized_name`으로 검색된다.
- 중복 결과가 한 번만 표시된다.
- 축제 선택 시 해당 월과 축제 패널이 열린다.
- 아티스트 선택 시 `/artist/[id]`로 이동한다.
- 축제 또는 아티스트 한쪽 결과가 없으면 빈 구역이나 불필요한 제목이 표시되지 않는다.
- 빈 검색어, 결과 없음, DB 오류가 정상 표시된다.
- 관련 테스트, 타입 검사와 변경 파일 ESLint가 통과한다.

## 제외 범위

- 검색 전용 페이지
- 검색 기록과 인기 검색어
- 자동완성 추천과 오타 유사도 검색
- 관리자 데이터 수정
- DB 테이블·RPC·RLS 변경

## 후속 개선점

- 결과가 많아지면 서버 검색 RPC와 페이지네이션을 별도 계획으로 검토한다.
- 필요하면 공개 축제에 연결된 아티스트만 표시하는 필터를 추가한다.

## 실제 구현 결과

- 모바일 기존 모달을 PC에서도 같은 방식으로 사용할 수 있게 연결했다.
- 축제 결과 다음에 아티스트 결과를 표시하고 빈 종류는 렌더링하지 않는다.
- 아티스트 별칭이 있으면 보조문구로 표시하고 없으면 `normalized_name`을 표시한다.
- 축제·아티스트 각각 최대 10개, 정확 일치와 시작 일치를 우선한다.
- 축제 검색 결과는 시작일이 최신인 순서로 표시한다.
- 검색 관련 단위 테스트 3개, 비증분 타입 검사, 변경 파일 ESLint가 통과했다.
- 전체 테스트 131개 중 검색을 포함한 129개는 통과했고, 기존 티켓 테스트 2개는 현재 읽기 전용 환경에서 임시 폴더를 만들 수 없어 실행되지 못했다.
- 모바일·PC localhost 실제 화면과 DB 검색 결과 확인이 남아 있다.

## 상단 검색·오늘 버튼 아이콘 정리

- 모바일과 PC 모두 검색 버튼은 `Search`, 오늘 버튼은 `CalendarDays` SVG만 표시한다.
- 두 버튼은 `44×44px` 클릭 영역을 유지하되 외곽선·배경·그림자는 제거한다.
- 평상시에는 테두리가 없고 호버할 때만 얇은 테두리를 표시한다.
- 화면 문구를 없애도 기능을 알 수 있도록 `aria-label`과 `title`을 유지한다.
- 기존 검색 모달과 오늘 이동 동작은 변경하지 않는다.
